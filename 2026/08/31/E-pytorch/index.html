1 Tensor 与 autograd（求导引擎）

是什么：Tensor 是 PyTorch 的数组（类似 numpy，但能跑 GPU、能记录计算图）。requires_grad=True 的 Tensor 会记录”怎么由它算出来的”，.backward() 后就能拿到梯度 .grad。

  • x.requires_grad_(True)：声明“我要对这个 x 求梯度”——之后所有以 x 为祖先的运算都会被记录进计算图。
  • x.grad：.backward() 之后，x 处累积的梯度就存在这里（对攻击来说，这就是 ）。

你在哪用：FGSM 攻击就是把 x（图片像素）设 requires_grad_(True)，前向算损失 → loss.backward() → 读 x.grad 得梯度方向 → x + ε·sign(x.grad)。这正是模块 J 的第一枪（对照 dl01 里手算的 dL/dx）。

1.1 两种乘法：逐元素乘 * / .mul() vs 矩阵乘 @ / .matmul()

新手最易混淆的一对。PyTorch 里”乘”有两种完全不同的含义，形状规则也不同：

写法 含义 形状规则
a * b / a.mul(b) 逐元素乘（Hadamard 积） a、b 形状必须完全一致
a @ b / a.matmul(b) / a.mm(b) 矩阵乘 a 的列数 必须 = b 的行数

💡 一句话记牢：* 是”位置对位置”，@ 是”行乘列求和”。 nn.Linear（你前面搭的网络）内部是 @（矩阵乘）；mask 遮罩、注意力门控、ReLU 后的逐元素操作用的是 * / .mul()。混淆这俩是高频 bug。

在哪用：FGSM 公式 x' = x + ε·sign(∇L) 里 ε 是标量，ε * sign(∇L) 就是逐元素乘（每个元素都乘同一个数）；注意力里的 scores * mask 把某些位置清零，也是 .mul()。

创建 tensor torch.tensor(数据) / torch.from_numpy(np_arr) / torch.rand/ones/zeros(shape) 加载数据、初始化权重都会用；from_numpy 与 numpy 共享内存（见下）

3 DataLoader 与训练循环

四步顺序为什么不能乱：梯度是累积的——不清空，上个 batch 的梯度会叠加进来；先 forward 后 backward；step 必须等 backward 算完梯度再更新。

train vs eval：model.train() 启用 Dropout、BatchNorm 用本 batch 统计；model.eval() 关掉 Dropout、BatchNorm 用全局统计量。推理/评测/对抗攻击测试必须 model.eval()，否则结果会随机漂移（见 D §5）。

6 常见误区

  1. 以为 .backward() 会自动更新参数 —— 它只算梯度；opt.step() 才是更新。忘了 step = 白训；忘了 zero_grad = 梯度累积错乱。
  2. 以为 x.grad 是”模型参数的梯度” —— 它是对 x（输入）的梯度。攻击要 x.grad（FGSM 用），训练要 w.grad（optimizer 用），同一个 backward 看你要谁的。
  3. 以为 model.eval() 只是”性能优化” —— 它改变函数行为（关 Dropout/BN），攻击评测不 eval() 指标必飘（D §5 的坑）。
  4. 以为数据不用搬设备 —— model.to("cuda") 后数据还在 CPU，forward 直接报错；两个都必须 .to(device)。
  5. 以为 CNN 必须手动展平 —— nn.Flatten() 就是干这个的；view(x.size(0), -1) 手写版等价。搞错维度是新手第一报错来源。
