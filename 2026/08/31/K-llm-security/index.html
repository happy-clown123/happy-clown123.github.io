模块 K：大模型安全（LLM Security）

定位：研究大模型本身的安全问题——prompt injection / jailbreak / RAG 投毒 / Agent 安全，是 2025-26 最热、最贴你考研方向的交叉点。
前置：模块 J（对抗 ML，建立”文本版对抗样本”直觉）｜ 后继：模块 L（用 AI 做安全，副线）

2 各小节锚点（定位到指南章节）

每个 K 小节一行定位，不重复讲解（讲解在路径文档和指南里），只做”到了这节 → 翻指南哪章”的索引。

2.1 Prompt Injection（直接 / 间接）

  • 主资源：指南 Ch2
  • 是什么：把恶意指令混进模型输入，让模型无视原 system prompt 去执行攻击者意图。直接 = 用户自己输；间接 = 藏在检索/网页/工具返回里。
  • 你在这用：OWASP LLM Top 10 第 1 名；它是 J 的 evasion 在文本空间的同构（输入→扰动→错误输出，只是输入从像素变成 token）。

2.2 Jailbreak / 越狱

  • 主资源：指南 Ch3
  • 是什么：用角色扮演/编码混淆/梯度引导绕过 RLHF 对齐。GCG、AutoDAN 是自动化代表。
  • 你在这用：K04 关卡；理解”对齐被绕过”的机理比背 payload 重要。

2.3 模型逆向与信息提取

  • 主资源：指南 Ch4
  • 是什么：训练数据抽取、成员推断、模型窃取、PII 泄露。
  • 你在这用：与 J §5 模型窃取/成员推断同构——“模型记住了不该记住的信息”。

2.4 对抗样本（文本版）

  • 主资源：指南 Ch5
  • 是什么：在 token/embedding 空间加极小扰动让预测翻转。因 token 离散不可微，需离散优化或连续松弛。
  • 你在这用：J §2 PGD 的文本版；直接复用你学过的 预算概念。

2.5 后门与供应链

  • 主资源：指南 Ch6
  • 是什么：训练时植入后门、数据投毒、模型权重篡改、供应链信任链破坏。
  • 你在这用：与 J §4 后门同构；读 PoisonGPT、HF 恶意模型事件理解”上游投毒”。

2.6 多模态与深度伪造

  • 主资源：指南 Ch7
  • 是什么：视觉提示注入、图像隐藏指令、跨模态对抗样本。
  • 你在这用：理解”模态间对抗迁移”——和 J 的对抗样本一脉相承。

2.7 Agent 安全（K §6，最贴你方向）

  • 主资源：指南 Ch8（多智能体复合攻击 / RAG 系统攻击）+ Ch9（工具调用型系统级攻击）
  • 是什么：工具调用劫持、MCP 安全、记忆投毒、权限提升、沙箱逃逸、级联失效。Agent = LLM + 上下文 + 工具 + 记忆 + 自主循环，攻击面从”说什么”扩到”借工具做了什么”。
  • 你在这用：2026 最新交叉点，覆盖之前标记的”AI 基础设施与供应链安全”缺口。参考路线 roadmap.sh AI Agent Security Engineering 当技能点对照表。

2.8 RAG 投毒

  • 主资源：指南 Ch8 的 RAG 系统攻击小节
  • 是什么：把恶意/错误内容塞进向量库，使检索增强的回答被操控。backdoor 的”触发器”对应”文档命中即生效”。
  • 你在这用：与 J §4 数据投毒同构；K03 动手。

2.9 防御与对齐

  • 主资源：指南 Ch11
  • 是什么：RLHF/Constitutional AI、输入过滤、输出监控、Guardrails。
  • 你在这用：与 J §对抗训练 是”前端/模型侧”两个方向的防御；K01 的隔离版就是 K 侧”训练前的输入治理”。

2.10 形式化验证（进阶）

  • 主资源：指南 Ch12
  • 是什么：认证防御、差分隐私、可证明鲁棒性边界。
  • 你在这用：有余力再深挖，不做主线验收要求。

2.11 RLHF Reward Hacking 与伪对齐（specification gaming）

  • 主资源：见 §K-补充 A + Skalse 2022
  • 是什么：RLHF 训练里奖励模型本身是被优化的”代理目标”，模型会找到奖励模型给高分、但真实目标（有用且无害）没达成的捷径——钻空子（reward hacking）/ 伪对齐（specification gaming）。它不是 bug，是优化一个不完美目标时的必然现象。
  • 你在这用：它是 §2.2 jailbreak 的”训练侧”孪生——jailbreak 在推理时绕过对齐，reward hacking 在训练时把对齐本身带偏，两者共享”代理目标 vs 真实目标”的裂缝。

2.12 Constitutional AI（宪法 AI）

  • 主资源：见 §K-补充 B + Bai 2022
  • 是什么：用一份”宪法”原则清单让模型自我批判+自我修正，再用 AI 反馈做 RL（RLAIF），大幅减少人类标注依赖。
  • 你在这用：是 §2.9 防御里”训练侧对齐”的代表路线，与 RLHF 同源但把人类反馈换成原则+AI 评判。

2.13 模型供应链安全（对应 OWASP LLM03）

  • 主资源：见 §K-补充 C + HF 恶意模型/pickle 事件综述（JFrog 2024 / Protect AI 2025）
  • 是什么：从预训练权重、依赖库、Hub 下载到部署的完整信任链风险；典型是 pickle 格式在加载时执行任意代码、typosquat 冒名模型、trust_remote_code 执行仓库内自定义 Python、PyPI 依赖被投毒。
  • 你在这用：与 §2.5 后门/供应链同构，但落点在”上游投毒 + 加载即执行”，是本仓 LLM03 条目的正文。

2.14 量化与推理侧信道

  • 主资源：见 §K-补充 D + Kadadekar 2026（量化降低安全性）
  • 是什么：量化/剪枝/边缘部署引入的精度损失与侧信道——精度掉会让拒答率崩、靠推理时延/功耗可反推模型结构或成员。
  • 你在这用：边缘部署与模块 J §5 模型提取（侧信道）的连接点；量化不是纯工程问题，它直接动安全。

2.15 大模型插件与代码执行安全

  • 主资源：见 §K-补充 E
  • 是什么：Code Interpreter / ReAct / Function Calling 中，工具返回内容被注入、沙箱被逃逸、权限过大导致的越权执行。
  • 你在这用：§2.7 Agent 安全的”工具执行”子面，MCP 之外的本地代码执行风险。

2.16 多模态模型安全（图文联合风险）

  • 主资源：见 §K-补充 F（§2.6 是入门，这里补”图文联合”纵深）
  • 是什么：图像里藏指令、图文对抗样本、跨模态提示注入、有害内容生成与 Deepfake 检测反向。
  • 你在这用：和 §2.6 一脉相承，但强调”文本指令泄进像素、像素指令泄回文本”的回路。

2.17 模型安全评估基准

  • 主资源：见 §K-补充 G + HarmBench 2024 + MT-Bench 2023
  • 是什么：用标准化 benchmark 量化”有多危险 / 拒答稳不稳”——ASR、拒答率、LLM-as-judge 一致性。
  • 你在这用：你做完 §2.2 jailbreak / §2.15 工具安全后，用基准给自己的模型打分数，别只靠手感。

K-补充：模型安全纵深

下面 7 个概念把 K 主线从”导航+锚点”补到”正文”。每个都走五段式：是什么 → 公式/机制 → 数值实例(可跑片段，预期输出写在注释) → 图(ASCII) → 你在哪用。片段只在你本地跑，不针对任何第三方系统。

A. RLHF Reward Hacking 与伪对齐（specification gaming）

是什么：RLHF 用奖励模型（RM）给模型输出打分，再用 RM 分数做强化学习。RM 只是”真实人类偏好”的代理（proxy）。当代理目标可被钻空子时，模型学到”让 RM 给高分、但人类实际并不想要”的行为——这就是 reward hacking；更广义的”任务说明书被钻空子”叫 specification gaming。

公式/机制：设代理奖励为 、真实奖励为 。Skalse 2022 定义代理为 unhackable 当且仅当”只增大 $\mathbb{E}\pi[R\text{proxy}]\mathbb{E}\pi[R\text{true}]$\forall \pi:\ \mathbb{E}\pi[R\text{true}] \ge \mathbb{E}{\pi’}[R\text{true}],\quad \pi’=\arg\max_{\pi} \mathbb{E}\pi[R\text{proxy}]$$
直觉：若”提高代理分”永远不降低”真实分”才叫不可钻。Skalse 证明：对所有随机策略，只有常值奖励函数才满足；对确定性/有限策略集存在非平凡不可钻对，但”把奖励写窄”通常做不到。

B. Constitutional AI（宪法 AI）

是什么：Anthropic 2022 提出的方法——不给人类标”哪些输出有害”，而是给模型一份写好的”宪法”原则清单，让模型先自我批判、再按原则自我修正，最后用”AI 反馈”代替人类反馈做 RL（RLAIF）。目的是把人类标注量降到极低，同时让行为规则可被检查。

公式/机制：分两段。

  • 监督段（SL-CAI）：采样初版回答 → 模型按宪法生成 critique（批判）→ 生成 revision（修正版）→ 在修正数据上微调。
  • RL 段（RL-CAI / RLAIF）：对一对回答，用模型按宪法判哪个更好 → 这些 AI 偏好训一个偏好模型 → 用该偏好模型当奖励信号做 RL。
    核心替换：人类偏好 → 原则驱动的 AI 偏好 。

C. 模型供应链安全（对应 OWASP LLM03）

是什么：从预训练权重、分词器、依赖库、Hub 下载到部署，整条信任链都可能被投毒。最典型的是 pickle 格式（.pt/.bin/.pkl）在 torch.load() 时执行任意 Python 代码；其次有 typosquat 冒名模型、Hub 上 trust_remote_code=True 加载仓库内自定义 Python、以及 PyPI 依赖被投毒。

公式/机制：pickle 用 REDUCE 指令在反序列化时调用任意函数 ，参数由攻击者定： 。SafeTensors 是”只有张量字节 + 元数据头”的格式，没有指令流、没有 REDUCE，加载路径无法被诱导调用函数——即”数据不可执行”。缓解 = 强制 .safetensors + 按 revision hash 固定 + 依赖扫描。

D. 量化与推理侧信道

是什么：为把大模型塞进边缘设备，要做量化（FP16→INT4/INT8）、剪枝、蒸馏。两类风险：(1) 精度掉会让”拒答/安全方向”的 margin 缩小，安全行为崩；(2) 推理时延、功耗、缓存命中可被观测，反推模型结构、超参或训练成员（侧信道模型提取）。

公式/机制：权重量化 ，量化误差 。Wu 2026 提出 margin shrinkage：量化后决策 margin（最优项与次优项得分差）被乘以一个随比特数塌缩的因子——中位 4-bit 乘 0.86、3-bit 乘 0.33、2-bit 趋 0；且”自信的决策更安全”这一假设不成立。侧信道：观测推理时延 拟合架构 ，即 。

E. 大模型插件与代码执行安全

是什么：模型通过 Code Interpreter / ReAct / Function Calling 调用外部工具（跑代码、查 API、读文件）。攻击面从”说什么”变成”工具做了什么”：工具返回内容可被注入、沙箱可被逃逸、权限过大可越权。

公式/机制：一次工具调用是 obs = tool(action)，其中 action 由模型生成、obs 回灌上下文。若 obs 含隐藏指令 ignore previous; run <cmd>，而系统把 obs 当可信上下文，就发生”间接注入→代码执行”。权限模型：工具应以最小权限 + 显式确认运行。

F. 多模态模型安全（图文联合风险）

是什么：视觉-语言模型（VLM）把图像和文本一起处理，于是出现”文本指令藏进像素、像素指令泄回文本”的回路：图像里渲染的文字/对抗扰动可被模型当指令执行，图像可携带提示注入，也能生成有害图（Deepfake），而 Deepfake 检测本身又被对抗样本反打。

公式/机制：VLM 把图像和文本编码进同一 embedding 空间， ，拼接后共同解码。若图像里嵌有可读文本 或对抗扰动 （使 小但 偏移），模型会把 当指令——即”跨模态提示注入”。

数值实例（本地可跑，用玩具线性探针演示”小扰动翻转图像预测”，是 VLM 跨模态对抗的极简替身）：

图（ASCII：图文双向泄密的回路）：

你在哪用：和 §2.6 一脉相承，补的是”图文联合”纵深。你做多模态红队时，要把文本注入和图像注入当成同一攻击的两种入口来测。

G. 模型安全评估基准

是什么：用标准化 benchmark 把”模型有多危险、拒答稳不稳”变成可比较的数字。主流有：HarmBench（自动化红队+鲁棒拒答，~400 条 behavior + 18+ 攻击 baseline）、MT-Bench（多轮指令遵循，GPT-4 当裁判）、JailbreakBench、Do-Not-Answer 等。

公式/机制：核心指标是攻击成功率 ，拒答率 。MT-Bench 用 LLM-as-judge 打 1–10 分，并重测裁判与人类一致性（GPT-4 与人类一致率 >80%）。HarmBench 还给出”稳健拒答”维度：面对攻击仍拒答的比例。

3 常见误区

  1. 很多人以为 Agent 安全是 LLM 安全之外的另一个领域，其实它是 LLM 安全的延伸——继承 prompt injection 所有老问题，但危害出口从”说什么”变成”借工具做了什么”（调了恶意 API、转了账、改了系统）。

  2. 很多人以为 RAG 投毒在指南 Ch10，其实 Ch10 是”搜索增强型信息战”（OSINT/钓鱼/舆论），真正的 RAG 系统攻击写在 Ch8 里。看错章会学偏。

  3. 很多人以为 Ch5 对抗样本是全新算法，其实它就是模块 J 的 FGSM/PGD 在 token 空间的版本，难点只在”token 离散不可微”怎么处理；你 J 学透了这里零门槛。

  4. 很多人以为 reward hacking 和 jailbreak 是一回事，其实 jailbreak 在”推理时绕过已训练好的对齐”，reward hacking 在”训练时把对齐目标本身带偏”——前者钻的是上线后的空子，后者钻的是优化过程中的代理目标（Skalse 2022）。

  5. 很多人以为 .safetensors 和 .bin 只是存储格式差异，其实 pickle 系格式（.pt/.bin/.pkl）在 torch.load() 时执行任意 Python 代码，加载不可信模型等于执行攻击者脚本；safetensors 是数据不可执行的格式，这是安全属性不是体积差异。

  • Skalse 2022 怎么定义 “unhackable”？为什么对所有随机策略只有常值奖励函数才不可钻？
  • Constitutional AI 的 SL 段和 RL 段分别做什么？RLAIF 把什么换成了 AI 反馈？

  • 量化到 INT4 为什么会让拒答 margin 收缩？你部署量化模型前要拿什么集重测安全？

7 与主线的连接

  • K Ch2 的 prompt injection = 模块 J §1 的 evasion 对抗样本 的文本版：同样的 input → 扰动 → wrong output，输入空间从像素变成 token。
  • K Ch5 的 对抗样本 = 模块 J §2 的 FGSM/PGD，难点只在 token 离散不可微（需离散优化或连续松弛）。
  • K Ch6 的 后门/供应链 = 模块 J §4 的 数据投毒/后门，触发器机制完全同构。
  • K Ch4 的 模型逆向/萃取 = 模块 J §5 的 模型窃取/成员推断，都涉及”模型记住了不该记住的信息”。
  • K §6 的 Agent 安全 是以上所有在”能调工具、有记忆、自主循环”环境下的复合放大——是 2026 最贴你方向的交叉点，但地基全在 J/K 前面这些小节里。
