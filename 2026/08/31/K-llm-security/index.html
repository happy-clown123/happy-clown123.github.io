大模型安全（K 模块）

模块 K：大模型安全（LLM Security）

定位：学习 LLM 与其应用的安全边界——prompt injection、jailbreak、数据泄露、RAG 投毒与 Agent 工具安全。你的重点是“外部信息如何影响 Agent 的实际动作”。
前置：基础 LLM/RAG 概念、Python 与 Web/API 权限；模块 J 用于补优化和评测知识，不必全部完成才进入 Agent 安全。后继：Agent 安全专题；模块 L 为应用副线。
验收：完成本地机制实验，写清威胁模型、正常/攻击对照、真实结果和边界；不要求打通固定关数，也不要求必须找到漏洞。

0 学习执行清单（按能力推进）

阅读与实验的对应边界：K01/K02 是确定性字符串规则，K03 是词频检索与模板生成，K04–K08 是策略与指标夹具。它们解释机制和工程边界，但没有测量真实 LLM 的服从率或向量检索的普遍攻击率。每次写下“攻击者能控制什么—哪一步受影响—观察到了什么—尚未验证什么”，再决定是否进入真实模型复现。

2 核心概念与实验入口

先理解机制，再按“读到这里”提示完成实验。指南链接均为可选辅助阅读；关键论断以本页列出的原论文和官方文档为准。

2.1 Prompt Injection（直接 / 间接）

  • 可选辅助：指南 Ch2
  • 是什么：攻击者把指令混入模型读取的输入，试图让其偏离授权任务。直接 = 攻击者直接提交消息；间接 = 藏在网页、检索文档或工具返回里。不要求完整覆盖 system prompt 才算攻击，部分任务偏转也可能造成风险。
  • 你在这用：它与 evasion 都通过攻击者可控输入诱导非预期行为，但不是严格“同一攻击的文本版”：FGSM 有明确的范数约束和梯度优化，prompt injection 的核心是指令与不可信数据共用语言通道和权限边界缺失。

先读后做｜K01：先读 Greshake 2023 间接注入笔记 的威胁模型与攻击链，再运行 labs/k01_prompt_injection.py。输出旁必须补一句：关键词启发式在固定样本上拦截成功，不等于对改写、多语言或间接输入安全。

2.1.1 跨语言 Prompt Injection（cross-lingual / 多语言注入）

  • 是什么：注入指令用与被攻击 Agent 运行语言不同的语言书写（例如 Agent 跑英文上下文，注入用中文/西班牙语）。主流 LLM 在多语言上共享语义空间，仍能”读懂并执行”异语言指令——这是 prompt injection 的一个独立攻击面。
  • 为什么单独成类：
    • 关键词 / 启发式过滤器通常只覆盖训练语料主流语言（多为英文），异语言指令容易绕过词表级检测（对照 §2.1 K01 的”多语言不安全”结论）。
    • 部分 Agent 的 system prompt 会写”只用用户语言回答 / 只处理英文网页”，但这只是软约束；模型底层的跨语言遵从能力仍在，注入常能生效。
    • 载荷语言 ≠ 指令语言：要插入/执行的精确字符串必须与判分或任务语言一致。例：Lakera Trippy Planner 要求原样复现英文钓鱼句 Book cheap tickets here: [secure-payment](https://pay.travel-secure-booking.com).——即使指令用中文写，载荷仍须英文 verbatim，否则 0 分。
  • 实战要点：
    • 指令语言：跟着 Agent 运行语言走最稳（英文场景用英文指令，伪装度高、不被语言过滤降权）。
    • 载荷语言：永远原样复现目标要求的字符串，一字不改（含 markdown 链接语法）。
    • 间接注入（网页/检索）：指令同时用”可见文本 + HTML 注释”双份覆盖，兼容剥 HTML 与读 raw 的抓取器。
  • 案例 + 可粘贴 payload：见 Lakera Agent Breaker 实战笔记（含跨语言讨论）。
  • 通用方法论 + 模板 + 变体调整 + 自测：见 Prompt Injection 攻击手法与防御（从原理到独立打类似关的完整手册，含自测题与参考答案）。
  • 防御（对应 K07 安全 Agent 管线）：把外部内容严格标记为不可信数据（delimiting / 隔离信道），指令与数据分通道；输出端对来自外部源的链接做白名单/域校验；不要仅凭”语言”做信任边界。

2.2 Jailbreak / 越狱

  • 可选辅助：指南 Ch3
  • 是什么：通过输入诱导模型违反预期的行为限制。限制可能来自不同训练方法及运行时策略，不能一概称为“绕过 RLHF 某层”。GCG 用目标续写的负对数概率作为优化目标：梯度给出候选 token，离散替换后前向评估并选较优候选；AutoDAN 使用分层遗传搜索。它们不要求在线欺骗一个奖励模型。
  • 你在这用：理解“对齐被绕过”的机理比背 payload 重要；检测器只能作为观测信号，不能代替工具授权。

学到这里立刻做｜K02：运行 labs/k02_jailbreak_detector.py，手算混淆矩阵与 TPR/FPR，并自己增加一个良性长文本和一个同义改写攻击。然后在 GCG 论文笔记 与 Many-shot Jailbreaking 笔记 中各找出“攻击预算/条件”，禁止跨论文直接比较百分比。

2.3 模型逆向与信息提取

  • 可选辅助：指南 Ch4
  • 是什么：训练数据抽取、成员推断、模型窃取、PII 泄露。
  • 你在这用：训练数据抽取关注恢复内容，成员推断判断某样本是否参与训练，模型窃取关注复制功能/参数；PII 也可能来自当前上下文或工具，不一定源于训练记忆。分别写清攻击者访问权限、目标和证据。

2.4 对抗样本（文本版）

  • 可选辅助：指南 Ch5
  • 是什么：通过字符/词/token 修改、追加后缀或其他受约束输入改变模型行为。token 身份是离散变量；连续 embedding 扰动是另一种设定，不能自动视为可输入的文本攻击。
  • 你在这用：对照 J 的连续优化思想，但文本预算应明确为编辑次数、后缀 token 数、查询次数或计算成本，另行验证语义保持。token ID 的数值距离没有通常的语义意义，不能直接套图像的 预算。

2.5 后门与供应链

  • 可选辅助：指南 Ch6
  • 是什么：训练时植入后门、数据投毒、模型权重篡改、供应链信任链破坏。
  • 你在这用：学习 J §4 的“干净行为/触发行为”对照，但后门是条件行为，触发不保证每次成功；供应链还包括恶意加载代码与依赖替换，不等于模型后门。

2.6 多模态与深度伪造

  • 可选辅助：指南 Ch7
  • 是什么：视觉提示注入、图像隐藏指令、跨模态对抗样本。
  • 你在这用：分别识别可见图中文字注入、图像扰动、合成内容滥用；是否跨模型/跨模态迁移必须实测。

2.7 Agent 安全（最贴你方向）

  • 可选辅助：指南 Ch8（多智能体复合攻击 / RAG 系统攻击）+ Ch9（工具调用型系统级攻击）
  • 是什么：工具调用劫持、MCP 安全、记忆投毒、权限提升、沙箱逃逸、级联失效。Agent = LLM + 上下文 + 工具 + 记忆 + 自主循环，攻击面从”说什么”扩到”借工具做了什么”。
  • 你在这用：专题路径、权限模型和 K04–K08 实验见 Agent 安全专题。K07 串起工具、记忆、审计与指标，K08 检测 MCP manifest rug pull。

现在转入专题：不要在本页一次跑完 K04–K08。打开 Agent 安全专题，按“威胁模型 → K04 工具 → K05 memory → K08 MCP → K06 指标 → K07 集成”的顺序推进；每一步完成后再回本页勾检查点。

2.8 RAG 投毒

  • 可选辅助：指南 Ch8 的 RAG 系统攻击小节
  • 是什么：污染 RAG 可读取的资料，可能植入错误事实，也可能夹带恶意指令。RAG 不一定使用向量检索；进入候选池、进入 top-k、被生成器采纳、最终目标达成是不同事件。
  • 你在这用：K03 演示检索侧与生成侧的分离。推理时污染检索语料不必修改模型训练数据或权重，不能直接等同训练投毒/后门。

学到这里立刻做｜K03：运行 labs/k03_rag_poisoning.py，记录恶意文档为什么进入 top-k；再修改关键词密度，观察排名变化。完成后回读 Greshake 2023 笔记，区分“进入检索结果”和“攻击目标动作真的发生”两个成功条件。

2.9 防御与对齐

  • 可选辅助：指南 Ch11
  • 是什么：RLHF/Constitutional AI、输入过滤、输出监控、Guardrails。
  • 你在这用：区分训练侧对齐、运行时检测和模型外强制授权。K01 只有运行时字符串启发式，没有训练过程；它不构成可靠隔离或对抗训练。

2.10 形式化验证（进阶）

  • 可选辅助：指南 Ch12
  • 是什么：在明确假设下证明特定性质。鲁棒性认证关注扰动集合内的行为；差分隐私约束相邻数据集产生输出分布的差异；两者不是同一种保证，也不自动阻止 Agent 越权。
  • 你在这用：有余力再深挖，不做主线验收要求。

2.11 RLHF Reward Hacking 与伪对齐（specification gaming）

  • 主资源：见 §K-补充 A + Skalse 2022
  • 是什么：RLHF 训练里奖励模型本身是被优化的”代理目标”，模型会找到奖励模型给高分、但真实目标（有用且无害）没达成的捷径——钻空子（reward hacking）/ 伪对齐（specification gaming）。这是可能出现的目标失配风险，不代表每次优化必然发生。
  • 你在这用：比较攻击/优化发生的阶段和目标。reward hacking 关注代理奖励失配；jailbreak 关注部署行为限制被绕过。二者可有关联，但不是同一机制。

2.12 Constitutional AI（宪法 AI）

  • 主资源：见 §K-补充 B + Bai 2022
  • 是什么：用一份”宪法”原则清单让模型自我批判+自我修正，再用 AI 反馈做 RL（RLAIF），大幅减少人类标注依赖。
  • 你在这用：是训练侧对齐的代表路线；原论文无害性标签来自 AI，有用性监督仍保留人类偏好，见补充 B。

2.13 模型供应链安全（对应 OWASP LLM03）

  • 主资源：见 §K-补充 C + Python pickle 安全警告 + PyTorch 序列化文档
  • 是什么：从预训练权重、依赖库、Hub 下载到部署的完整信任链风险；典型是 pickle 格式在加载时执行任意代码、typosquat 冒名模型、trust_remote_code 执行仓库内自定义 Python、PyPI 依赖被投毒。
  • 你在这用：补充 §2.5 的制品来源与加载路径审计；此处 LLM03 指 OWASP 2025 版本编号。

阅读与迁移：先读本页 §K-补充 C，列出模型权重、adapter、Python 依赖、MCP tool 四种制品各自该固定的身份/版本/hash。随后运行 K08，把“manifest 变化需重审批”的思路迁移到 LoRA adapter；注意 K08 没有验证模型文件是否无后门。

2.14 量化与推理侧信道

  • 主资源：见 §K-补充 D + Kadadekar 2026（量化后的质量不能替代安全测试）
  • 是什么：量化可能改变行为，质量保持不保证安全保持；时延/功耗/缓存等可观测量是另一类侧信道研究。能推断什么取决于访问条件、噪声、对照数据和攻击方法，不是看到时延即可推断训练成员。
  • 你在这用：部署优化后重测行为；若研究侧信道，另行定义可观测面与推断目标，不从量化误差直接推出隐私泄漏。

2.15 大模型插件与代码执行安全

  • 主资源：见 §K-补充 E
  • 是什么：Code Interpreter / ReAct / Function Calling 中，工具返回内容被注入、沙箱被逃逸、权限过大导致的越权执行。
  • 你在这用：§2.7 Agent 安全的”工具执行”子面，MCP 之外的本地代码执行风险。

2.16 多模态模型安全（图文联合风险）

  • 主资源：见 §K-补充 F（§2.6 是入门，这里补”图文联合”纵深）
  • 是什么：图像里藏指令、图文对抗样本、跨模态提示注入、有害内容生成与 Deepfake 检测反向。
  • 你在这用：分别测试图中文字被误作指令、对抗扰动改变感知、生成内容风险，不用一个“像素泄漏”概念代替全部机制。

2.17 模型安全评估基准

  • 主资源：见 §K-补充 G + HarmBench 2024 + MT-Bench 2023
  • 是什么：用标准化 benchmark 量化”有多危险 / 拒答稳不稳”——ASR、拒答率、LLM-as-judge 一致性。
  • 你在这用：你做完 §2.2 jailbreak / §2.15 工具安全后，用基准给自己的模型打分数，别只靠手感。

K-补充：模型安全纵深

下面 7 个概念把 K 主线从”导航+锚点”补到”正文”。每个都走五段式：是什么 → 公式/机制 → 数值实例(可跑片段，预期输出写在注释) → 图(ASCII) → 你在哪用。片段只在你本地跑，不针对任何第三方系统。

A. RLHF Reward Hacking 与伪对齐（specification gaming）

是什么：RLHF 用奖励模型（RM）给模型输出打分，再用 RM 分数做强化学习。RM 只是”真实人类偏好”的代理（proxy）。当代理目标可被钻空子时，模型学到”让 RM 给高分、但人类实际并不想要”的行为——这就是 reward hacking；更广义的”任务说明书被钻空子”叫 specification gaming。

公式/机制：令 和 为同一策略的代理/真实期望回报。在指定策略集合 上，unhackable 要求不存在“代理升、真实降”的策略对：

这不是“只检查代理最优策略”的条件。按 Skalse 原文 v2 §5.1 定理 1 / 推论 1，在其 MDP 与策略集合假设下，非平凡且不可钻的奖励对必须等价（对策略排序一致）；不能省略“等价”情形而说只有常值奖励才可行。有限策略集的结论不同，也不能据此宣称实际系统必然被攻击。

B. Constitutional AI（宪法 AI）

是什么：Bai 2022 以原则清单指导批判/修订，再用 AI 偏好反馈训练无害性。原实验仍保留有用性的人类偏好数据及人类评估，不是整个训练流程没有人类数据。

公式/机制：分两段。

  • 监督段（SL-CAI）：采样初版回答 → 模型按宪法生成 critique（批判）→ 生成 revision（修正版）→ 在修正数据上微调。
  • RL 段（RL-CAI / RLAIF）：对一对回答，用模型按宪法判哪个更好 → 这些 AI 偏好训一个偏好模型 → 用该偏好模型当奖励信号做 RL。
    替换范围是无害性偏好标注；原实验的有用性监督仍有人类反馈。下面两个函数只是固定模板，没有模型判断，也没有 SL/RL 训练。

C. 模型供应链安全（对应 OWASP LLM03）

是什么：风险来自权重、分词器、依赖、仓库代码及部署过程。恶意 pickle 在不受限制的反序列化中可执行代码；后缀 .pt/.bin/.pkl 不能单独证明文件内容或加载路径。trust_remote_code=True 也会引入仓库自定义代码的信任决策。

公式/机制：pickle 可通过 REDUCE 等机制调用对象指定的函数。下面仅加载自己刚生成的无害对象，不加载下载文件。PyTorch 文档 说明 weights_only=True 会限制反序列化能力，但仍不是完整安全沙箱；不要为消除报错而盲目关闭限制。safetensors 没有 pickle 式执行指令流，但不能证明权重无后门、加载库无漏洞或外围代码安全。版本/hash 固定用于追溯，不等于来源可信。

D. 量化与推理侧信道

是什么：量化改变数值表示，可能改变模型行为；安全性不能只用通用质量分数代替。侧信道研究的是时延、功耗、缓存等额外观测，不是量化的同义词。

机制与证据：简单舍入模型为 ；真实量化还有位宽、范围、裁剪、分组和校准设置。Kadadekar 2026 预印本 在其指定模型/量化矩阵中观察到质量与拒答变化方向不一致。这支持“部署版本要直接测安全”，不支持“所有 INT4 必然破坏拒答”或统一的 margin 缩小系数。

E. 大模型插件与代码执行安全

是什么：模型通过 Code Interpreter / ReAct / Function Calling 调用外部工具（跑代码、查 API、读文件）。攻击面从”说什么”变成”工具做了什么”：工具返回内容可被注入、沙箱可被逃逸、权限过大可越权。

公式/机制：一次工具调用可写作 obs = tool(action)，其中 action 由模型提出、obs 回灌上下文。不可信 obs 若被误作指令，可能改变后续动作；只有不安全动作又通过授权/执行边界，才会产生越权效果。模型外网关应验证工具、参数、资源与用户权限，高影响动作再要求明确确认。

F. 多模态模型安全（图文联合风险）

是什么：视觉-语言模型（VLM）接收图文输入，图中的可见文字可能被错误当作指令；对抗像素扰动则可能改变感知/生成行为。这与深度伪造生成及其检测是相关但不同的风险，不能把一次分类翻转叫作提示注入成功。

公式/机制：不同 VLM 使用投影、交叉注意力等方式融合图像与文本表征，不能统一假定为同一个编码器和简单拼接。图像中的文字可能被错误当成指令；对抗扰动则可能改变感知或下游行为。两类风险需要分别验证： 只说明输出变化，尚不等于跨模态提示注入成功。

G. 模型安全评估基准

是什么：用标准化 benchmark 把”模型有多危险、拒答稳不稳”变成可比较的数字。安全评估资源包括 HarmBench、JailbreakBench、Do-Not-Answer 等。MT-Bench 主要测多轮对话质量和指令遵循，可作效用参考，不应直接归类为攻击安全基准。使用任何基准都要记录版本、任务、评分器和样本分母。

公式/机制：先声明分母：全部预定 case 数 、有效运行数 、成功数 、拒答数 、运行错误数 。可报告 （全体成功比例）与 （有效运行条件下 ASR），同时报 ；拒答不等于正确完成任务。评分器的判定规则也要冻结。HarmBench 官方项目 以具体行为与评估流程为准，不能统一改写成“没拒答就成功”。

3 常见误区

  1. Agent 安全包含模型行为、应用鉴权、工具执行和供应链问题；不是只靠加强 system prompt 就能解决。
  2. RAG 文档被检索到不等于模型服从；错误事实污染也不一定包含恶意指令。
  3. 文本优化不是 FGSM/PGD 换输入名：离散可行域、语义保持、目标函数、可访问梯度和预算都需重新定义。
  4. jailbreak 是违反部署行为限制，reward hacking 是代理奖励与目标失配；GCG 不必查询奖励模型。
  5. 文件扩展名不是安全证明；safetensors 减少 pickle 式代码执行面，但不能保证模型行为无后门或外围代码安全。
  6. 扫描器命中不是已确认漏洞，零命中也不是安全证明；必须复核检测器、分母、服务错误与正常任务效用。

6 检查点（合上正文再答）

  • 画出一次直接/间接注入的入口与信任边界；哪些约束必须由模型外程序执行？
  • GCG 优化哪个概率目标？梯度在哪里用？为什么这不是“后缀骗过 RM”或直接对 token ID 做 PGD？
  • RAG 的候选池、top-k、生成采纳、攻击目标达成四步，哪一步有证据？K03 没验证什么？
  • 如做 garak/在线挑战，是否固定了范围、版本与预算，保留失败/错误并人工复核？零发现是否如实记录？
  • 运行 K01/K02，给一个正常误报和一个攻击漏报；手算 TPR/FPR，分母为零怎么办？
  • 按专题顺序做 K04–K08；沿 K07 审计事件手算指标，解释 K08 不会证明远程工具实现安全。
  • 数据抽取、成员推断、模型窃取各自需要什么访问条件、恢复什么对象？PII 为什么也可能来自上下文？
  • 对给定两条策略判断是否“代理升、真实降”；Skalse 定理中的策略集合与奖励等价条件为何不能省略？
  • CAI 的 SL/RL 两段做什么？原论文哪些监督来自 AI，哪些仍来自人类？固定模板代码模拟了什么？
  • pickle 与 safetensors 的边界是什么？为什么 hash、受限加载器和沙箱各自仍不等于模型无后门？
  • 舍入玩具是否是真正 INT4 量化？真实部署怎样控制模型、模板、解码与评分器后重测？
  • 图中文字注入、图像对抗扰动、Deepfake 有何区别？预测改变为什么不等于越权成功？
  • ASR 的分母是什么？错误怎样统计？为什么拒答率、正常任务效用和动作授权要分别测？
