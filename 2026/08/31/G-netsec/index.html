1 网络分层：数据怎么从 A 到 B

实际用 TCP/IP 四层（链路层 / 网络层 / 传输层 / 应用层）；教材常讲 OSI 七层（多物理层、会话层、表示层）。记住封装方向即可：

  • IP（网络层）：负责寻址和路由，把包送到对端主机。无连接、不可靠（不保证到达、不保证顺序）。
  • TCP（传输层）：面向连接、可靠、有序。握手建连、丢包重传、流量控制。
  • UDP（传输层）：无连接、不可靠但快。DNS 查询、视频通话、QUIC 都跑在 UDP 上。

2 TCP：可靠传输怎么来的

三次握手（建立）：SYN → SYN+ACK → ACK。目的：双方确认对方的收发能力，并同步初始序列号，防止历史重复连接被当成新连接。

四次挥手（断开）：FIN → ACK → FIN → ACK。比建立多一步，因为服务器收到 FIN 后可能还有数据要发，只能先 ACK、发完再 FIN（半关闭）。客户端最后进入 TIME_WAIT（等 2MSL）确保最后的 ACK 到达、旧报文消散。

安全意识：SYN 泛洪 = 攻击者发大量 SYN 但不回 ACK，耗尽服务器半连接队列 → 一种 DDoS。理解它你就懂了”为什么需要 SYN Cookie”。

3 HTTP 与 HTTPS：差的不只是个 S

HTTP HTTPS
传输 明文（TCP 80） TLS 加密（TCP 443）
风险 内容可被窃听/篡改、无身份认证 机密性 + 完整性 + 服务器身份认证
性能 快 TLS 1.3 仅 1-RTT，几乎无感

HTTPS = HTTP + TLS。TLS 负责三件事：机密性（对称加密）、完整性（AEAD/签名）、身份认证（证书 + CA）。

TLS 1.3 握手（ECDHE，1-RTT）

关键点：

  1. ClientHello 带 client_random、支持的密码套件、以及 ECDHE 公钥（key_share）。
  2. ServerHello + 证书 + CertificateVerify（对握手消息签名）+ Finished 一次性发回；服务器拿到 client 的公钥后已经能算出会话密钥。
  3. 客户端验证证书链与签名，发 Finished → 双方会话密钥一致，之后全用对称加密（AEAD，如 AES-128-GCM）。

性质：

  • 前向保密：每次 ECDHE 临时密钥不同，即便服务器长期私钥泄露，也解不开历史流量。
  • 1-RTT：比 TLS 1.2 少一轮往返；更多握手消息被加密。
  • 0-RTT 恢复：重连首包即可带加密数据，但牺牲部分前向保密——对对外 API 要慎重。

2026 视角：HTTP/3 基于 QUIC（跑在 UDP 上，内置 TLS 1.3，0-RTT 建连），现代站点已广泛支持。DNS 也走向加密：DoH（DNS over HTTPS）、DoT（DNS over TLS），避免查询被窃听。

4 DNS：域名怎么变成 IP

递归解析流程：客户端 → 本地解析器（ISP/公共 DNS 如 8.8.8.8）→ 根 → .com TLD → 权威服务器 → 拿到 A 记录原路返回。解析器会缓存（TTL 控制时长）。

与攻击的关系：

  • 默认 DNS 是明文 UDP 53 → 可被劫持/污染（返回假 IP，把你引到钓鱼站）。
  • 缓解：DoH / DoT 加密查询；自建解析器时校验响应来源。

5 常见攻击面总览（听懂即可）

攻击 在哪一层 一句话
MITM（中间人） 传输/网络 攻击者夹在通信中间窃听/篡改，常见于公共 WiFi、无 TLS
DNS 劫持/污染 应用(DNS) 返回假 IP，引流到恶意站
ARP 欺骗 链路 局域网内冒充网关，劫持同网段流量
DDoS 网络/传输 海量流量打瘫目标（SYN 泛洪、UDP 反射放大）
端口扫描 传输 枚举目标开放端口，侦察攻击面
明文嗅探 全层 没加密的流量谁都能看

你作为 AI 安全研究者，重点是理解这些词出现在报告/论文里时指什么，以及你的实验流量是否加密——比如评测模型窃取攻击时，API 走 HTTPS 是前提。

6 密码学速览（够用就停）

  • 对称加密（AES）：加解密同一把密钥，快，适合大量数据。密钥分发是难点。
  • 非对称加密（RSA / ECC）：公钥加密、私钥解密；或私钥签名、公钥验签。慢，用于密钥协商与身份认证。
  • 哈希（SHA-256）：单向摘要，定长输出，用于完整性校验、证书指纹。
  • 数字签名：用私钥对消息哈希签名，别人用公钥验证”确实是你发的且没被改”。TLS 证书靠它证明服务器身份。
  • HMAC：用密钥的哈希消息认证码，验证消息完整且来自持有密钥的一方（API 鉴权常用）。

不必深究算法内部。记住对称=快/需共享密钥、非对称=慢/解决分发与认证、哈希=不可逆摘要、签名=身份认证这四象限即可。

7 和 AI 安全的连接点（这节最重要）

  • prompt injection 经 HTTP 注入：间接注入的 payload 常藏在网页/API 响应里，经 HTTP 进到 LLM 上下文 → 懂 HTTP 才懂注入入口。
  • 模型窃取（model extraction）经 API：攻击者反复调用推理 API，用输入/输出对重建模型。理解 HTTPS/鉴权才能评估”调用是否被窃听、如何限速防御”。
  • 对抗样本传输：评测时对抗样本作为请求/文件传来传去，明文通道会被中间人篡改 → 实验环境要用 TLS 或隔离网络。
  • 红队基础设施：你跑 garak/PyRIT 扫描一个对外 LLM 服务，本质是构造并发送大量 HTTP 请求——懂握手、懂证书校验，才知道”为什么有的服务要关证书验证才能测”。

9 常见误区

  1. 以为 HTTPS 就绝对安全 —— HTTPS 保证传输机密性，但端侧（服务端代码、客户端脚本）漏洞、恶意证书链、0-RTT 部分前向保密牺牲都是现实风险。
  2. 以为”三次握手是三次都要传数据” —— 三次交换的是 SYN/SYN-ACK/ACK 标志与序列号，为的是同步双方能力；真正的数据在握手完成后才传。
  3. 以为 DNS 查询是”一次问到答案” —— 是递归+迭代的多级查询（客户端→解析器→根→TLD→权威），任何一级被劫持都能引流到钓鱼站。
  4. 以为对称加密更弱 —— AES 很安全；难的是密钥分发，所以才有非对称加密+TLS 握手来协商对称密钥。
  5. 以为攻击者都在”网络层” —— 现代攻击（含 prompt injection 注入）大多在应用层：HTTP 请求里藏 payload、API 响应里带指令。网络层是地基，应用层才是主战场。

10 检查点（自测）

  • HTTPS 怎么保证通信安全？跟 HTTP 的区别？（机密性/完整性/身份认证分别靠什么）
  • DNS 解析流程是什么？为什么明文 DNS 会被劫持，DoH/DoT 怎么缓解？
  • TCP 三次握手每一步在交换什么？为什么需要三次而不是两次？
  • 对称加密 / 非对称加密 / 哈希 / 数字签名 各自解决什么问题？
  • 模型窃取攻击和 HTTPS/API 鉴权有什么关系？（用自己的话答）
