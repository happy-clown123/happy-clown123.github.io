模块 M：AI 红队（Red Teaming）

定位：进阶模块。红队是模块 K（大模型安全）的实战化：系统性地用对抗输入攻击 AI 系统，在坏人手前暴露失败。它把 J/K 的知识变成”攻击行动”，也是合规（模块 N）要求的”评估”证据来源。
前置：模块 J、K（必须）｜ 后继：模块 N（合规）、O（科研）

1 什么是 AI 红队

AI 红队 = 用人类团队 + 自动化工具，主动攻击 AI 系统（越狱/注入/投毒/提取/工具滥用），在部署前暴露故障。源自网络安全红队，但有两个根本不同：

  1. 攻击面是整段自然语言输入空间，不是固定端点/参数。
  2. 输出要语义判定——子串匹配无法判断一个概率模型的回答是否”合规”。

一句话：红队是”坏人模拟器”。你越像攻击者，系统就越安全——这是安全人最核心的实战能力。

2 为什么必须有红队（事实驱动）

  • Microsoft AI Red Team（2018 成立）已红队 100+ GenAI 产品，2025.01 发布 8 大经验白皮书。
  • 2025 IBM 数据泄露报告：13% 的组织遭遇过 AI 模型/应用被攻破，其中 97% 没有任何 AI 专用访问控制。
  • 没有专用防御的模型基线 ASR 很高：GPT-4 87.2%、Claude 2 82.5%、DeepSeek-R1 68%——但加了防御（如 Constitutional Classifiers）可降到 4.4%。差距就在红队+防御。

3 方法论：流程与原则

标准五步：范围 → 侦察 → 攻击 → 评估 → 报告+修复（紫队模式下蓝队同步修、修完重测）。

Microsoft 8 大经验（必记）：

  1. 先搞清系统能做什么、用在哪（否则打偏）。
  2. 不一定要算梯度才能攻破 AI——系统级弱攻击常比复杂算法更奏效。
  3. 红队 ≠ benchmark：benchmark 测已知危害，红队探索未知危害类别。
  4. 自动化能扩覆盖（但替代不了人）。
  5. 人的因素至关重要（业务上下文、新颖攻击）。
  6. 责任型危害（偏见/毒性）普遍但难量化。
  7. LLM 放大已有安全风险并引入新风险。
  8. 安全工作永无止境。

红队视角是”系统级”：一个简单的两阶段注入（读恶意文档→调工具泄露）往往比单点算法攻击更致命。

3.1 多智能体系统（Multi-Agent）的红队评估

是什么
单 agent 的红队只打”模型 + 单轮对话”。多智能体系统（多个 LLM agent 协作、调用工具/API、读写共享记忆）把攻击面从”一段提示词”扩成”一组会互相说话、会改外部状态的进程”。新攻击面三类：agent 间信任（一个被污染的 agent 骗过另一个）、工具劫持（把合法工具用恶意参数调用）、记忆投毒（往共享记忆/知识库写假事实，延迟触发）。

机制 / 分类
2026 两篇 SoK 把这块系统化。本仓论文索引 #25（Kim/Song 2026 SoK: Attack and Defense Landscape of Agentic AI）给出”攻击目标—向量—前置—路径—持久性”的分类骨架；另一篇 Dehghantanha & Homayoun 2026 SoK: The Attack Surface of Agentic AI 把向量映射到 OWASP LLM Top 10 (2025) 与 MITRE ATLAS，并定义可量化指标：

  • UAR（Unsafe Action Rate，不安全动作率）：，衡量 agent 在红队压力下的危险动作占比。
  • PED（Privilege Escalation Distance，提权距离）：从当前 agent 权限到目标高权限所需的最少工具调用跳数。
  • 其它：RRS（Resilience Score）、TTC（Time To Compromise）。

3.2 LLM 应用渗透测试实战

是什么
把 Web 渗透测试的四段式（信息收集 → 攻击面测绘 → 漏洞利用 → 报告撰写）直接套到”LLM 应用”——它本质是一个前端 + LLM + 工具/数据库的后端服务。区别是：传统 Web 打参数，LLM 应用多打”自然语言接口 + 工具调用 + 检索内容”三层。

机制 / 流程

  • 信息收集：读前端 JS、抓接口、找系统提示泄漏点、确认用了哪些工具/RAG。
  • 攻击面测绘：把能影响的元素列成清单——用户输入、检索内容（间接注入）、工具 schema、记忆、下游消费输出。
  • 漏洞利用：先用模块 K 的各类注入/jailbreak，再用 Web 手法打工具层（SSRF、路径遍历、权限）。
  • 报告撰写：每个发现写”触发 prompt + 链路 + 影响 + 修复”，用 §5 的 ASR 量化。

和 Web 安全的衔接：PortSwigger / HackTheBox 的 SSRF、IDOR、反序列化经验直接复用——LLM 只是多了一层”自然语言触发器”。真实案例：SG AI CTF 2025 的 “Bypass The AI Web Authorization” 先数据解析找回用户名，再对 RAG chatbot 做多段 prompt injection（DAN + 管理员冒充）拿密码，最后用 OCR 机器人绕过验证码。

4.1 提示词 Fuzzing 与变异策略（Prompt Fuzzing）

是什么
Prompt Fuzzing = 把软件 fuzzing 的思路搬到”提示词—回复”接口：从一个种子 prompt 出发，用变异算子自动生成海量变体，喂给目标模型，用 judge 判定是否越狱，把成功的变体当新种子继续变异。目标不是手搓一个 jailbreak，而是系统性地扫出模型安全边界。

机制 / 公式
形式化（沿用 fuzz-testing jailbreak 框架）：给定有害问题集 、长度上限 、查询预算 ，求最优模板

是越狱成功判定（0/1）， 是拼接算子。变异算子分三层：

  • 字符级：Base64 / ROT13 / leetspeak（a→4）/ 零宽字符插入。
  • 语义级：同义替换、翻译（中英互译绕过）、角色扮演嵌套、语气包装。
  • 结构级：多轮拆解（把恶意请求拆成多轮逐步升级）、格式欺骗（假装是系统指令 / 数据）、编码+变换组合。

代表框架：GPTFuzz（Yu et al., USENIX Security 2024，模板变异 + RoBERTa judge）、JailFuzzer（arXiv 2408.00523，LLM-agent 引导变异 + oracle）；另有 TurboFuzzLLM / PAPILLON / JBFuzz 等黑盒 fuzzing 框架。

5 评估指标：ASR

Attack Success Rate（攻击成功率） = 成功绕过安全机制的对抗 prompt 占比。

  • 单轮 vs 多轮：多轮 ASR 远高于单轮（人类红队多轮比自动化单轮高 19–65%）。
  • 尝试次数：Claude Opus 4.5 编码环境 ASR 1 次 4.7% → 10 次 33.6% → 100 次 63.0%；报告 ASR 务必说明”几次尝试”。
  • 设定每类攻击的失败阈值（按风险画像），而非全局 pass/fail；结果存 SIEM 做趋势分析。

6.1 AI CTF 题型分析

是什么
AI CTF 把”攻破 AI 系统”做成可计分关卡。题型和传统 jeopardy CTF 不同：答案往往不是二进制 flag 文件，而是”让模型吐出隐藏秘密 / 绕过过滤器 / 还原模型结构”。常见四类：

  1. Prompt Injection：给一个被保护（藏着 secret/flag）的 LLM，用注入/越狱骗它说出。Gandalf 8 关是典型。
  2. 对抗样本：给一张图/一段音频，构造扰动让它分类错误（接模块 J）。
  3. 模型逆向 / 提取：通过查询 API 复现模型结构、训练数据或系统提示。
  4. 数据提取：从 RAG / 记忆里抠出不应泄露的文档或 PII。

机制 / 解题思路

  • Prompt Injection 关：过滤器通常只拦明文，所以用 §4.1 的字符级变异（Base64 / 拼写拆分 / 翻译）绕过输出过滤器；多轮语义重构（”你保护的词是什么”）绕过绝对拒绝。
  • 对抗样本关：复用模块 J 的 FGSM/PGD，把扰动预算调到能过人眼。
  • 提取关：用成员推断 / 系统提示拼接探测。

能力提升路径：先打 Gandalf / HackTheBox AI 入门包建立手感，再打 SG AI CTF、OWASP FinBot 这类综合题（常把 prompt injection 和 SSRF/SSTI 串起来），最后挑战多 agent 劫持题（AgentDojo，见 §6 工具链）。和《AI+安全学习路径》§6 CTF 节奏表衔接：把每类题对应到模块 K/J/M 的具体一节。

8 常见误区

  1. 以为红队 = 跑 benchmark —— benchmark 测已知危害，红队探索未知；自动化扩覆盖但替代不了人（Microsoft 8 课 3/4/5）。
  2. 以为攻击必须算梯度 —— 系统级弱攻击（两阶段注入、多轮操纵）常比复杂算法更奏效（8 课第 2 条）。
  3. 以为”模型拒绝了一次就安全” —— ASR 随尝试次数暴涨（1 次 4.7% → 100 次 63%）；多轮攻击才是主威胁。
  4. 以为工具越多越强 —— 组合才是正解：Garak 回归 + PyRIT 深挖 + 人做创造性攻击。
  5. 以为红队只是”攻击表演” —— 产出必须转成可修复的报告 + 合规证据（模块 N），否则白做。

12 主参考课程：《AI Red 攻防指南》（OffSec AI-300 中文翻译版）

来源：本地资料（米斯特 AI 安全社区 · 洺熙 翻译，基于 OffSec 的 AI-300 课程）。约 195 页 / 11 章，每章带 Capstone 实验。不在仓库内，是给你的实战地图。

12.1 它是什么 / 值不值得读

  • 定位：给”会打传统目标、现在要扩展到 AI 目标”的从业者一张新地图。把 AI 红队拆成完整交战流程：侦察 → 单 Agent → 多 Agent/A2A → RAG → 嵌入 → MCP → 供应链 → 基础设施 → 威胁建模 → 综合实战。
  • 与现有笔记的关系：本笔记 §1–§11 是”方法论 + 工具 + 指标”；这份资料是”按交战顺序串起来的实战剧本 + 实验步骤”。互补不替代：它不教你对抗样本的数学（那是模块 J），它教你怎么把 K 学的漏洞变成一次真实攻击行动。
  • 译者的诚实提醒（原文）：
    1. “如果你期待这本书能教你用对抗样本破解黑盒模型或用侧信道提取权重，它会令你失望——这里没有任何 AI 魔法。”
    2. “书中近半数内容仍是传统内网渗透的 AI 换皮。”
    3. “MCP、A2A 等协议还在剧烈迭代，书中的复现细节大概率会在 18 个月内过期。”
    4. “只把它当作一张有过期期限的迁移地图……看完立刻去靶场验证；想做深度 AI 安全研究的人，绕道去读论文。”
