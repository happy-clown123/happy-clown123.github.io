逆向工程基础（Reverse Engineering）

定位：理解别人写的代码在干什么。做对抗样本分析、模型攻击评估、恶意代码检测时，有时需要读二进制或别人的模型代码。
前置：模块 G（网络）、B（Python/Linux）｜ 后继：模块 L（恶意代码检测）、M（红队）
及格线：能用 Ghidra 打开一个编译好的 C 程序找到 main 并看懂它调用了什么；跑通 i01（单字节 XOR 破解）；能说清 ELF/PE 导入表对恶意代码检测的意义。

1 静态 vs 动态分析

  • 静态：不运行，直接看文件结构 / 反汇编 / 反编译（Ghidra、objdump、strings）。快、安全。
  • 动态：把程序跑起来，用调试器 / hook 看运行时行为（GDB、Frida、strace）。能看真实执行路径，但有风险（恶意样本要放虚拟机/沙箱）。

流程见下图：先 strings 找明文，再静态读反编译伪代码，卡住才上动态。

2 汇编基础（x86-64 够用）

你不需要写汇编，但要能读。关键点：

  • 寄存器：RAX（返回值/累加）、RDI/RSI/RDX/RCX（第 1~4 个函数参数，System V 调用约定）、RSP（栈指针）、RIP（指令指针）。
  • 常见指令：mov（赋值）、cmp（比较，设标志位）、je/jne（等于/不等于则跳）、call（调用函数）、ret（返回）、push/pop（入栈/出栈）。
  • 调用约定：Linux x86-64 前 6 个整型参数走 RDI, RSI, RDX, RCX, R8, R9；返回值在 RAX。
  • 栈帧：函数开头常是 push rbp; mov rbp, rsp，局部变量在栈上。看到 cmp eax, 0x...; je success 这类就是”比对密码/密钥后跳转”。

直觉：汇编就是把”如果密码==secret 就成功”变成 cmp + 条件跳转。逆向就是反过来，从跳转条件推出它在比什么。

3 文件格式：ELF vs PE

ELF（Linux/Unix） PE（Windows .exe/.dll）
头部 ELF Header + Section/Program Header DOS Header(MZ) + PE Header
代码节 .text .text
数据节 .data / .bss .data / .rdata
导入/导出 动态符号表（PLT/GOT） Import Table / Export Table
入口 _start → __libc_start_main → main AddressOfEntryPoint → main/WinMain
扩展 .o / 可执行 / .so .exe / .dll

为什么重要：做恶意代码检测时，PE 的 Import Table 能暴露它调用了哪些 Windows API（如 CreateRemoteThread、InternetOpen → 可疑）；ELF 的 .dynamic/GOT 暴露它依赖哪些共享库。

6 和 AI 安全的连接点

  • 模型窃取 / API 分析：攻击者调用推理 API，分析返回结构（延迟、分布、错误信息）来重建模型。懂二进制/协议有助于理解”返回里泄露了什么”。
  • 恶意代码检测：AI 驱动的安全（模块 L）常要判别 PE/ELF 是否恶意；理解文件头与导入表是特征工程的基础。
  • 读模型代码：PyTorch 模型加载、推理脚本往往是普通 Python/C++；逆向思维（从行为反推逻辑）= 读开源模型代码的思维。
  • 防御模型提取：理解对方怎么”读”你的模型，才能设计抽取抵抗（如限制 API 返回置信度位数）。

8 常见误区

  1. 以为逆向 = 必须会写汇编 —— 现代主流是读反编译的 C 伪代码（Ghidra/IDA 自动生成），汇编只是看懂跳转条件的辅助。
  2. 以为静态分析能解决一切 —— 加壳/混淆/动态解密让静态反汇编失效；真实恶意样本必须动态沙箱跑（但要在隔离环境）。
  3. 以为 strings 只对明文有效 —— 恶意代码常把关键字符串 XOR/Base64 处理过，strings 扫不到；要结合 i01 这类解密思路。
  4. 以为模型代码/权重也要”逆向” —— 开源模型直接读源码即可；逆向思维（从行为反推逻辑）适用于闭源 API：分析返回结构、延迟、错误信息来推断实现。
  5. 以为 Import Table 是”证据” —— 它只是静态特征：合法软件也调用 CreateRemoteThread；要结合行为链判断（这就是 AI 恶意代码检测要特征+行为联合的原因）。

9 检查点（自测）

  • ELF 和 PE 文件格式的区别？（头部、导入表、入口各有什么）
  • 在虚拟机里，用 Ghidra 反编译一个简单的 hello.c，找到 main 函数并说出它调用了什么
  • 静态分析和动态分析各解决什么问题？为什么恶意样本要在沙箱跑？
  • x86-64 下函数前几个参数存在哪些寄存器？返回值在哪？
  • 跑通 i01：密文密钥是多少、明文是什么？频率评分怎么挑出正确密钥

及格线：能用 Ghidra 打开一个编译好的 C 程序，找到 main 函数，大概看懂它调用了哪些函数/系统调用。

资源：《汇编语言》王爽（入门）；《程序员的自我修养》（链接/装载）；Ghidra 官网（ghidra-sre.org，需 JDK 21）；pwn.college。了解即可，不用深入。
