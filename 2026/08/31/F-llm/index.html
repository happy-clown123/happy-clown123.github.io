Transformer 与 LLM 基础（Transformer & LLM）

定位：先理解模型如何读取上下文、产生下一 token，再研究输入如何影响行为。Prompt injection 涉及指令与外部数据的信任混淆；jailbreak 涉及模型及系统的安全行为，二者都不能仅凭某一层 attention 或 RLHF 解释。
前置：模块 D（深度学习）、B（Python）｜ 后继：模块 K（大模型安全）、E（PyTorch）
及格线：能画出 Q/K/V 注意力流程并手算一步 scaled dot-product attention（llm02）；能手写/讲清 BPE 合并逻辑（llm01）；能区分预训练、SFT、偏好对齐与运行时权限边界，不把 jailbreak 简化成“绕过 RLHF 的某一层”。

1 Self-Attention：Q、K、V 是什么

是什么：让每个 token 的输出表示融合整个序列的信息。每个 token 投影出三个向量：

  • Q（Query 查询）：”我在找什么信息”
  • K（Key 键）：”我能提供什么信息的标签”
  • V（Value 值）：”我实际携带的信息”

符号逐个解释： 输入投影后的矩阵（每行一个 token）； 所有 token 两两的点积相似度； 缩放因子——防止维度大时点积数值爆炸把 softmax 推成 one-hot；softmax 归一成权重（每行和为 1）；乘 得到加权融合表示。

你在哪用：attention 权重可用来观察 token 间的信息混合，但“权重高”不等于“对输出有因果作用”。分析 jailbreak 时，attention 图最多是生成假设的观察工具；注入的工程根因是可信指令和不可信数据被序列化到同一上下文，且模型没有可强制执行的权限边界。

2 Transformer 架构：Encoder 与 Decoder

  • Encoder（编码器，如 BERT）：双向看全句，适合”理解类”任务（分类、NLU）。encoder-only。
  • Decoder（解码器，如 GPT）：只看已生成部分（掩码自注意力），自回归逐 token 生成，是今天 LLM 的主流。decoder-only。
  • Encoder-Decoder（如原始 Transformer、T5）：翻译类任务。

Multi-Head Attention = 把 Q/K/V 投影成多组、并行算多次 attention 再拼起来，让模型同时关注不同子空间（语法、语义、指代…）。

2.1 先把形状与因果遮挡算清楚

单个头中，若序列长为 ，则 、 ；Q @ K.T 得到 (n,n)，按行 softmax 后再乘 V 得到 (n,d_v)。第 行表示“位置 i 从哪些位置取信息”，不表示模型给各条指令分配了权限。

读图顺序：选一行 query → 看该行可见的 key → 先把未来位置分数设为负无穷 → 只在可见位置归一化。第 0 行仅看自己，所以权重为 [1,0,0]。乘以零不等于屏蔽：exp(0)=1，该位置仍会分到权重；若整行都被屏蔽则 softmax 未定义，应检查 mask，而不是把 NaN 当正常输出。

配图实验｜LLM02 第二部分：运行 LLM02，比较双向与因果两张权重矩阵。先预测修改最后一个 token 后，因果模式的前两行输出应保持不变，再运行脚本中的断言。最后解释：网页中的恶意文字若已经位于可见的历史上下文，causal mask 为什么不会自动拦截它。

你在哪用：causal mask 限制每个位置只能看到自己及之前的 token。它不直接推出“payload 越靠后越容易成功”；位置效应还受模型、任务、指令角色和上下文长度影响。比较注入位置时要固定内容与预算、测试多个位置和正常对照，不能把架构可见性当作攻击成功规律。

读完再继续：回看本文 §1 的矩阵形状，自己画出 decoder 中 causal mask 的上三角遮挡。这里先不要做 jailbreak 实验；你需要先能解释“因果遮挡”和“安全权限边界”为什么不是同一件事。

4 预训练 → SFT → RLHF 训练流程

是什么：让”续写机器”变成”对齐助手”的三步。

  1. 预训练（Pre-train）：在海量无标注语料上预测下一个 token，学到语言和世界知识（base model）。
  2. SFT（监督微调）：用”指令-回答”高质量 pair 教模型按人类期望的格式/任务回答。
  3. 偏好对齐（RLHF 是一种实现）：
    • 训一个奖励模型（Reward Model），学习”人类更喜欢哪个回答”；
    • 用 PPO 强化学习，让模型生成的回答在奖励模型上拿高分——把”人类偏好”编进权重。

你在哪用：Jailbreak 是推理时输入诱导出违背安全意图的行为。它可能暴露 SFT/偏好对齐的分布外泛化失败，也可能利用 system prompt、应用编排或输出检查的缺陷。所以不存在一个可被精确指认的“RLHF 护栏层”；必须同时检查模型行为和系统权限。

阅读任务：阅读 InstructGPT 的方法图和训练阶段说明，画一张“预训练 → SFT → 偏好数据/奖励模型 → 策略优化”的流程图。每个阶段写清输入、训练目标和它不能提供的系统权限保证；完成后再进入 K 模块的 jailbreak。

5 Tokenization 与 prompt injection 的关系

是什么：模型吃的是 token（不是字符），同一句话的切分方式由 tokenizer 决定。BPE（Byte Pair Encoding）是主流：从字符开始，反复合并”出现频率最高的一对相邻符号”，直到达到词表大小。

攻击含义：

  • 切分改变输入表示：Unicode、空格和罕见字形会影响 token 序列与长度，但“切得整齐”不是攻击成功的必要条件。记录原始字节、可见文本、token ID 和生成结果，才能区分编码变化与行为变化；仅凭切分不同不能断言绕过成功。
  • 拼接边界：即使 API 用 role 区分 system/user/tool，底层仍需把它们序列化为模型可读的 token 序列。role 会影响模型行为，却不是操作系统式强制访问控制；真正的安全边界必须放在模型之外（工具白名单、参数校验、最小权限、人工确认）。

学到这里立刻做｜LLM01：运行 labs/llm01_bpe_mini.py，在不改算法的前提下增加一条包含中英文和特殊字符的语料，记录前三次 merge。验收不是“脚本跑完”，而是你能解释不同 tokenizer 为什么会改变 payload 形态，却不会凭空创造权限边界。

7 常见误区

  1. 以为”token 就是单词” —— BPE 词表里大量是子词（ing、pre、甚至单个字节）。这直接决定注入 payload 的”切分边界”，同一 payload 在不同 tokenizer 下行为不同。
  2. 以为 attention 权重可以直接解释”模型在想什么” —— 权重高 ≠ 因果关系；分析 jailbreak 时用它做线索可以，当证据不行。
  3. 以为 RLHF 让模型“变善良”了 —— RLHF 改变的是行为分布，不是可强制执行的权限控制；敏感操作仍要在模型外限权。
  4. 以为 jailbreak 只是“RLHF 第三步失效” —— 它是系统级行为，可能涉及训练、提示模板、编排、过滤和权限多个环节，应用对照实验定位。
  5. 以为 prompt 越长越安全 —— 上下文越长，注入面越大（system + 历史 + 检索内容 + 工具输出都在里面）。

10 与主线的连接

  • → 模块 K §2.1 prompt injection：注入的本质是“拼接边界 + 指令/数据共用语言通道”——本模块 §5 的 tokenizer 直觉和 §1 的注意力机制帮助理解输入表示，但权限控制仍在模型外。
  • → 模块 K jailbreak：区分模型训练形成的行为倾向与模型外权限控制；用正常对照、攻击输入和执行轨迹定位失效环节，不能声称找到了某个“RLHF 护栏层”。
  • → 模块 J §3 evasion：FGSM 在连续输入上沿梯度符号走一步；GCG 利用梯度筛选离散 token 替换候选并评估候选损失。二者共享梯度直觉，但优化空间、约束与搜索步骤不同。
  • → 模块 E（PyTorch）：本模块概念在 E 里变成可运行代码；dl01/llm02 的 torch 验证就是 E 的最小实践。
