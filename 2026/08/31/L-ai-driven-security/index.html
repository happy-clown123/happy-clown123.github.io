1 一个要先钉死的认知：用 AI 做安全 ≠ 研究 AI 安全

研究的问题 例子
主线 J / K AI 系统的安全问题 怎么骗过分类器、怎么注入 LLM
副线 L（本模块） 用 AI 解决安全问题 用分类器识别恶意流量、用 LLM 做告警分诊

两者关系：L 造的 AI detector，正是 J 的攻击对象。下面 §5 会用代码演示这一点——这是本模块最该记住的一课。

2 AI 驱动的威胁检测（经典落点）

传统基于规则/签名的检测对付不了零日与新型攻击，ML 补的是”从数据中学习模式”。

场景 常用模型 特征怎么来
恶意流量 / 入侵检测 RF、GBT、SVM、孤立森林 NetFlow、包长序列、会话统计
恶意代码检测 RF、DNN、图神经网络 API 调用序列、权限组合、函数调用图（FCG）
钓鱼 / 垃圾邮件 BERT/RoBERTa 文本分类、CNN 视觉 邮件正文语义、发件人、URL 视觉相似度
异常行为（UEBA） 自编码器、LSTM、隔离森林 用户/实体基线行为，偏离即告警
威胁情报 聚类、嵌入 + RAG 把 IOC、CTI 报告聚成攻击活动

2025 产业落地很猛：Cisco 开源 Foundation-Sec-8B、Trend Micro 推 Cybertron 安全 LLM、SentinelOne/CrowdStrike 的”行为 AI”在端点实时阻断勒索/无文件恶意软件，处理量级到 10 万 EPS、延迟 <1 秒。

3 AI-SOC 与 SecOps（LLM 进来后的形态）

LLM 改变了安全运营中心（SOC）的工作方式，2025 年关键词是 Agentic SOC：

  • 告警分诊（Triage）：copilot 把几百条日志压缩成人类可读时间线，自动生成 Splunk/KQL 查询、YARA 规则。
  • SOAR 集成：AI 驱动 playbook 自动隔离端点、禁用账号（高风险动作保留 HITL 人工确认）。
  • 威胁情报融合：把观测到的 TTP 自动映射到 MITRE ATT&CK / MITRE ATLAS。
  • 红蓝对抗演练：用数字孪生环境让 AI 扮演红队与蓝队自动找防御差距。

注意：这里的”AI 帮安全运营”本身又引入模块 K 的攻击面——copilot 可能被 prompt injection 误导生成错误处置，所以 Agentic SOC 也要套 K 的分层防御。

4 攻击者也在用 AI（双刃剑）

防守用 AI，攻击也用 AI，形成军备竞赛：

  • AI 生成钓鱼：用 LLM 写高度个性化、无语法错误的鱼叉邮件，点击率比手写高 ~60%。
  • 语音克隆（vishing）：合成高管声音授权转账，2024 多起损失超千万澳元。
  • 自动漏洞利用：AI 指纹化技术栈、关联 CVE、自动生成可用 exploit，披露到利用的窗口从”周”缩到”小时”。
  • 多态恶意软件：生成式 AI 重写自身代码规避签名检测。

结论：74% 的 CISO 报告过去 12 个月遭遇过 AI 增强攻击（2025 调研）。”用不用 AI”不再是问题，比对手先用上、且用得安全才是。

5 关键交叉点：你的检测器就是模块 J 的靶子

这是本模块最该记住的一课，也是 L 与 J 的硬连接。

恶意代码检测器的输入是”特征向量”（如 API 调用集合）。攻击者在保持恶意功能不变的前提下，往样本里加一些”良性特征”（比如多申请几个无害权限、加几个良性 API 调用），就能把特征向量推到决策边界另一侧，让检测器判为良性。

  • 特征空间攻击（feature-space）：直接在特征向量上加扰动（数学干净，但生成的”特征”可能对应不到真实文件）。
  • 问题空间攻击（problem-space）：直接改真实文件（加代码/权限），约束是”功能不变 + 不像人为篡改”。这才是现实威胁。

2025 实测：Android 恶意软件的问题空间攻击在 12 个主流检测器上 ASR 达 80%–97%（SMAttack 等），且扰动 <7%。”对抗恶意软件即服务（adversarial-malware-as-a-service）”已被证明可规模化。

防御这个检测器（回到模块 J 的方法论）：

  • 对抗训练：把对抗样本加入训练集——但问题空间攻击因”功能保持”约束复杂，难度远高于图像。
  • 问题空间专用防御：在特征提取前做语义校验、检测”不该出现的特征组合”、模型架构加固。
  • 混合静态+动态：光靠静态特征易被绕过，结合行为分析（运行时监控）。

6 实验清单（Labs）

Lab 目标 脚本 依赖 硬件/成本 过关判据
l01 训练恶意检测器 + 特征空间逃逸：不加扰动检出率 ≈1.0，沿”良性方向”微调特征后逃逸率显著上升 labs/l01_detector_evasion.py numpy, scikit-learn CPU，秒级 输出对照：检出率 ≈1.0 → 逃逸率 >0.5；能解释”为什么检测器不可信”

7 常见误区

  1. 以为”L 也是主线” —— 不是。J/K 决定你进什么公司，L 决定你进去后能否干活。篇幅与深度都不得超过 J/K 任一模块。
  2. 以为”我的检测器足够准就不会被绕过” —— 精度与对抗鲁棒性正交（模块 J §10 误区 2）：99% 精度的检测器照样被微小特征扰动打穿（l01 会演示）。
  3. 以为特征空间攻击≈问题空间攻击 —— 前者数学干净但可能不现实；后者（保持功能改文件）才是 80%+ ASR 的现实威胁。
  4. 以为 Agentic SOC 只是”更聪明的工具” —— 它引入模块 K 的攻击面：copilot 被注入可能生成错误处置，必须套 K 的分层防御。
  5. 以为”攻击者用 AI”是未来时 —— 已是现在时：AI 钓鱼点击率高 60%、自动利用窗口缩到小时级；防守方必须同等火力。

8 检查点（自测）

  • “用 AI 做安全”和”研究 AI 的安全”本质区别是什么？（L vs J/K）

  • 为什么 AI 安全检测器本身会被对抗样本绕过？（提示：它就是一个 ML 模型 = J 的靶子）
  • 特征空间攻击 vs 问题空间攻击区别？哪个才是现实威胁
  • 跑通 l01，贴出攻击前后检出率对照——记住这个教训
  • Agentic SOC 里的 copilot 为什么又引入模块 K 的攻击面

9 与主线的连接

  • → 模块 J §3 evasion：L 的检测器就是 J 的攻击对象——l01 就是”特征空间的 FGSM”；l01 的逃逸实验 = J01 的检测器版。
  • → 模块 J §6 防御：对抗训练/输入校验在 L 里是”防御你自己的检测器”；问题空间攻击让对抗训练更难。
  • → 模块 K §6 Agent 安全：Agentic SOC 的 copilot 是 LLM 应用，Memory Poisoning / 注入直接威胁告警处置质量。
  • → 模块 M（红队）：L 检测器的对抗评估就是 M 的例行动作。

主线回顾：L 是副线，但 §5–§6 把 J 和 L 焊死——你做安全检测越依赖 ML，就越要按 J 的对抗鲁棒方法论保护自己造的模型。这正是”AI 安全人 = 既懂攻击又懂防御”的体现。
