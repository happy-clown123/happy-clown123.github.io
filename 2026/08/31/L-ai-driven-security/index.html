1 一个要先钉死的认知：用 AI 做安全 ≠ 研究 AI 安全

研究的问题 例子
主线 J / K AI 系统的安全问题 怎么骗过分类器、怎么注入 LLM
副线 L（本模块） 用 AI 解决安全问题 用分类器识别恶意流量、用 LLM 做告警分诊

两者关系：L 造的 AI detector，正是 J 的攻击对象。下面 §5 会用代码演示这一点——这是本模块最该记住的一课。

2 AI 驱动的威胁检测（经典落点）

传统规则/签名对已知模式可解释且高效，但对未覆盖的变体可能召回不足；ML 可以从数据中学习补充信号，也会受到分布漂移、误报和对抗规避影响。两者通常是组合关系，而不是 ML 自动替代规则。

场景 常用模型 特征怎么来
恶意流量 / 入侵检测 RF、GBT、SVM、孤立森林 NetFlow、包长序列、会话统计
恶意代码检测 RF、DNN、图神经网络 API 调用序列、权限组合、函数调用图（FCG）
钓鱼 / 垃圾邮件 BERT/RoBERTa 文本分类、CNN 视觉 邮件正文语义、发件人、URL 视觉相似度
异常行为（UEBA） 自编码器、LSTM、隔离森林 用户/实体基线行为，偏离即告警
威胁情报 聚类、嵌入 + RAG 把 IOC、CTI 报告聚成攻击活动

产业产品已把 ML/LLM 用于检测、告警摘要、查询生成和响应编排，但厂商公布的吞吐、延迟和检出数字通常绑定特定数据与部署配置。阅读产品材料时至少记录数据来源、基线、误报率、时延口径和人工审批点，不能把单一宣传指标当成跨环境能力。

3 AI-SOC 与 SecOps（LLM 进来后的形态）

LLM/Agent 正在成为安全运营中心（SOC）的一种辅助形态，常被称为 Agentic SOC；下面列的是可能能力，不代表所有产品都能可靠自动完成：

  • 告警分诊（Triage）：把日志整理为候选时间线，辅助生成 Splunk/KQL 查询或 YARA 规则；输出仍需在原始证据上复核。
  • SOAR 集成：为 playbook 提出处置建议；隔离端点、禁用账号等高影响动作应受最小权限、审批和回滚约束。
  • 威胁情报融合：辅助把观测到的行为映射到 MITRE ATT&CK；只有证据与定义匹配时才能确认 TTP。
  • 红蓝对抗演练：在隔离、授权环境中生成候选攻击/防御步骤；结果不能替代人工验证。

注意：这里的”AI 帮安全运营”本身又引入模块 K 的攻击面——copilot 可能被 prompt injection 误导生成错误处置，所以 Agentic SOC 也要套 K 的分层防御。

4 攻击者也在用 AI（双刃剑）

防守用 AI，攻击也用 AI，形成军备竞赛：

  • AI 辅助钓鱼：LLM 可降低批量改写、翻译和个性化邮件的成本；点击率变化取决于受测人群、消息、基线和防护，不能套用一个通用提升比例。
  • 语音克隆（vishing）：合成声音可提高冒充的逼真度；具体损失和是否由 AI 导致必须依据个案证据判断。
  • 漏洞研究与利用辅助：模型可辅助技术栈识别、CVE 检索和候选代码生成，但可利用性仍依赖目标版本、环境验证和授权边界。
  • 恶意代码变体生成：生成模型可能帮助改变表面代码或混淆形式；能否保持功能并逃逸具体检测器必须实测。

调查口径不要写错：Bitdefender 2025 Cybersecurity Assessment 调查了六个国家、任职于 500 人以上组织的 1,200 名 IT 与安全从业者；对“过去 12 个月，组织是否经历过你认为涉及 AI 的攻击”这一自报问题，63% 的总体受访者回答“是”，美国子样本为 74%。这不是“74% 的 CISO”，也不是经独立事件取证确认的攻击率。它能说明受访者感知到的风险，不能单独证明 AI 攻击的真实基准率或效果。

5 关键交叉点：你的检测器就是模块 J 的靶子

这是本模块最该记住的一课，也是 L 与 J 的硬连接。

恶意代码检测器的输入可以是”特征向量”（如 API 调用集合）。在某些允许添加特征的威胁模型中，攻击者会尝试加入良性行为片段或无关调用，把提取后的表示推向良性区域；但特征向量中可写出的变化未必能落实为合法文件，也未必保持恶意功能或被特征提取器按预期读取。

  • 特征空间攻击（feature-space）：直接在特征向量上加扰动（数学干净，但生成的”特征”可能对应不到真实文件）。
  • 问题空间攻击（problem-space）：修改真实对象并满足格式、语义与功能约束。它更接近部署威胁，但可实现性、功能保持和隐蔽性都必须逐项验证；特征空间实验主要用于机制学习和候选上界，不能自动转成问题空间结论。

论文结果要绑定威胁模型：SMAttack 在论文指定的 Android、基于 API 特征的黑盒恶意软件检测设置中，通过子图模仿与 APK 操作评估了 12 个检测器，报告 ASR 为 80%–97%。这是该论文数据、检测器、查询接口和成功判据下的结果；不能外推为所有 Android 样本、所有检测器或本仓 l01 的预期结果，也不能据此断言攻击已经以服务形式规模化。

防御这个检测器（回到模块 J 的方法论）：

  • 对抗训练：把威胁模型内可实现的对抗样本加入训练；离散文件格式、功能保持与特征映射使问题空间样本生成通常更复杂，训练效果仍受攻击覆盖度限制。
  • 问题空间专用控制：在特征提取前做格式/语义校验，检查异常组合并审计模型和特征流水线；这些都是候选控制，不是单独的安全保证。
  • 混合静态+动态：结合静态结构与运行时行为，减少对单一信号的依赖；动态分析同样可能被环境识别、延迟触发等手法规避，需要自适应评测。

6 实验清单（Labs）

读图后做 L01，并写出外推边界：运行 l01_detector_evasion.py，对照上方检测流水线标出“原始对象 → 特征 → 分类结果”。本例只改数值特征；请为每个改动补问“能否生成合法文件、是否保持原功能、是否仍被正确提取为该特征”。答不出时，只能报告 feature-space 结果，不能写成真实恶意软件绕过率。最后阅读模块 J §7，并按下面口径留证：

  • 干净恶意样本数 n_malicious、其中被检出的 n_detected，检出率为 n_detected / n_malicious；同时另报良性样本上的误报，不能只看恶意子集。
  • 脚本当前打印的逃逸率以全部恶意测试样本为分母；更严格的条件逃逸率应写成“原本被检出、攻击后变成良性”的数量除以 n_detected。两种口径不得混写。
  • 配置预算是每步仅减小尚未逃逸样本的各维特征 0.05、最多 10 步并裁剪到 [0,1]，所以相对原向量的配置上界为 L∞ ≤ 0.50；再从实际数组报告每条样本的步数、改变坐标数和 L∞ 距离。配置上限不等于每条样本的实际扰动。
Lab 目标 脚本 依赖 硬件/成本 过关判据
l01 训练合成恶意检测器并评估定向特征压低启发式 labs/l01_detector_evasion.py numpy, scikit-learn CPU，通常秒级，依机器而异 保存种子与原始计数；分别报告干净检出率、全体恶意分母逃逸率、条件逃逸率和实际扰动；允许攻击无效或结果不稳定，但必须解释威胁模型与 feature-space 边界

更完整的复现可参考 ART，并按估计器能力选择攻击：可微模型才适合直接使用 FGSM/PGD，树模型要使用兼容的树攻击、迁移或查询式方法。本 lab 的随机森林攻击没有求梯度，只是反复把合成特征往预设“良性方向”压低并查询标签；不要把它称为 FGSM。

7 常见误区

  1. 以为”L 也是当前主线” —— 对你当前的 Agent 安全方向，J/K 优先，L 用来补检测、SOC 和安全工程语境；若未来岗位或研究问题改变，再调整深度，不用给所有人规定同一篇幅。
  2. 以为”我的检测器足够准就不会被绕过” —— 干净分布精度不等于指定威胁模型下的鲁棒性；l01 只用合成数据演示二者要分开测，不证明任意高精度检测器都会被“微小”扰动打穿。
  3. 以为特征空间攻击≈问题空间攻击 —— 前者的向量修改可能不可实现；后者还必须验证格式、功能和特征提取结果。论文中的高 ASR 也只能在原实验设置内解释。
  4. 以为 Agentic SOC 只是”更聪明的工具” —— 它引入模块 K 的攻击面：copilot 被注入可能生成错误处置，必须套 K 的分层防御。
  5. 以为”攻击者用了 AI”就等于攻击一定更强 —— AI 可以降低内容生成、检索和变体制作成本，但效果取决于任务、数据、目标环境与人工复核；用受控实验和事件证据评价，不引用脱离分母的宣传数字。

8 检查点（自测）

  • “用 AI 做安全”和”研究 AI 的安全”本质区别是什么？（L vs J/K）
  • 列举 3 个 AI 驱动检测的真实场景（恶意流量/代码/钓鱼/UEBA 任选）
  • 为什么 AI 安全检测器本身会被对抗样本绕过？（提示：它就是一个 ML 模型 = J 的靶子）
  • 特征空间攻击与问题空间攻击分别验证什么？为什么前者的 ASR 不能直接当成后者的部署风险
  • 跑通 l01，贴出攻击前后的原始计数、各指标分母、条件逃逸率与实际 L∞/L0 扰动；若攻击失败也如实分析
  • Agentic SOC 里的 copilot 为什么又引入模块 K 的攻击面

9 与主线的连接

  • → 模块 J §3 evasion：L 的检测器就是 J 的攻击对象。l01 是定向压低特征并查询标签的教学启发式，与 J01 都展示输入修改可能改变模型输出，但 l01 不是 FGSM，也没有验证真实文件可实现性。
  • → 模块 J §6 防御：对抗训练/输入校验在 L 里是”防御你自己的检测器”；问题空间攻击让对抗训练更难。
  • → 模块 K §2.7 Agent 安全：Agentic SOC 的 copilot 是 LLM 应用，Memory Poisoning / 注入直接威胁告警处置质量。
  • → 模块 M（红队）：L 检测器的对抗评估就是 M 的例行动作。

主线回顾：L 是副线，但 §5–§6 把 J 和 L 焊死——你做安全检测越依赖 ML，就越要按 J 的对抗鲁棒方法论保护自己造的模型。这正是”AI 安全人 = 既懂攻击又懂防御”的体现。
