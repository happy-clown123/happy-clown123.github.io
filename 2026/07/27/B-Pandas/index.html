pandas 笔记

Pandas

本文行动导航：把本文示例整理成一张 10–20 行的模拟访问日志；完成过滤后找出失败请求，完成 groupby 后统计每个 IP 的请求数/失败率，完成缺失值后解释删除与填充的影响。产物保存为代码和 CSV，随后在 L01 中观察“特征处理如何影响安全检测器”。

跟着敲：每段代码两种跑法都行，推荐法 A边敲边看：

  • 法 A（推荐）：开交互解释器 python（或 python3；想要高亮/补完可 pip install ipython 后用 ipython，非必须）→ 直接粘贴每段代码 → 立刻看输出 → 改条件再跑。最贴合”看输出、想变化”的学法。
  • 法 B（写文件）：把代码存成 pandas_lab.py，python pandas_lab.py 运行；适合 §4/§6 多行演练，方便反复跑、留档。练习脚本建议放 ~/py-lab（自己建，别用 /tmp，也别和 linux 的 /tmp/linux-lab 混）：mkdir -p ~/py-lab && cd ~/py-lab。
    默认环境：本机 WSL（Ubuntu）。先确认 pandas 已装（个人环境直接装；共享服务器务必先激活自己的 venv/conda 再装）：

安全味贯穿：把”服务器访问日志”当成 DataFrame 来过滤、统计、分组——这正是蓝队日常。

1 创建与读取

只有日志本身是 CSV 格式时才能直接用 pd.read_csv("access.log")；JSONL 可用 pd.read_json(..., lines=True)，服务器原始文本日志需先按实际格式解析。扩展名 .log 不决定文件格式。

💡 DataFrame = 一张带列名的二维表；每列有自己的 dtype。读入后核对 dtypes、行数与关键字段；状态码读成字符串时，比较操作可能报错或不符合预期。

2 查看与选择

loc 按索引标签、iloc 按整数位置——别混。

💡 标签（loc）是行叫什么名字，位置（iloc）是第几个（从 0 数）。两者偶尔不同，混淆时优先用 iloc，最不容易出错。

3 条件过滤（安全核心操作）

追问：怎么选出”method 是 POST 且 status 是 403”的记录？（提示：用 & 连接两个条件，每个条件加括号）

💡 df["status"] >= 400 先算出一串 True/False（布尔掩码），再用它筛行。多条件必须用 &/| 且每个加括号：(条件1) & (条件2)——因为 Python 里 and/or 和位运算优先级不同，不加括号会报错或结果错。

4 分组聚合（统计攻击来源）

蓝队直觉：出现次数异常高、或 403/500 密集的 IP，优先排查。

💡 groupby 是”先按某列分组 → 每组各自统计 → 拼回一张结果表”。蓝队用它数”每个 IP 干了多少次”，谁异常高谁优先查。

5 缺失值与去重

日志里常有空字段，分析前先看清缺失情况。

💡 日志常有空字段或重复的脏数据，isna().sum() 先看缺多少，dropna()/drop_duplicates() 再清理，否则后面的统计会偏。

6 简单特征工程

删除空值和重复行是分析决策：两个相同 IP、状态码的请求可能是真实重复行为，不能随手去掉。应优先用 request_id 等业务唯一键判断重复，并记录清理前后的行数。

学到这里立刻做：给示例增加一条完全相同的请求和一条缺失状态码的请求，分别比较“保留”“删除”“标记未知”三种处理对请求数、失败数、失败率的影响。先写分母口径：所有请求，还是仅有已知状态码的请求？400/500 表示请求失败，不能直接当成恶意攻击标签；误把错误码当真值会污染后续 L01 的评测。

这一步把原始日志变成”每 IP 的异常计数”——已经是一张可喂给检测模型的特征表了。

💡 (df["status"] >= 400).astype(int) 把”是否异常”从布尔变成 0/1 数字列——这就是把文字日志转成”模型能吃的数字特征”的关键一步。

7 与 numpy 打通

pandas 负责”读表/清洗/分组”，numpy 负责”数值计算”，两者接力。

💡 模型（PyTorch / sklearn）吃的是 numpy 数组，所以清洗完用 to_numpy() 把列交出去。pandas 管”表”，numpy 管”算”，在 ML 流水线里接力。

学完标准：能用 pandas 读表、按条件过滤、groupby 聚合、处理缺失值、造简单特征列，并把列转成 numpy 数组。够用就停——B 阶段（Python/Linux/Git/Numpy/Pandas）到此收口，直奔模块 C（经典机器学习）。
