1 数组创建与属性

改成 4 条样本再看 shape 怎么变？

💡 这四个是 numpy 数组的”身份证”，读代码/调模型天天要看：

  • shape：各维度大小，(3,) 一维、(3,3) 二维；模型输入几乎都是 (样本数, 特征数)。
  • ndim：维度数（= len(shape)），向量是 1、矩阵是 2、批量图/序列常 3~4。
  • dtype：每个元素的类型，默认 float64；训练常用 float32 省显存，类型不对会报错或精度异常。
  • size：元素总数（= shape 各维乘积），x.size 等价于 np.prod(x.shape)。
    想换类型用 x.astype(np.float32)，显存紧张时必做。

2.1 随机数可复现性专题

这块看着”基础”，其实直接决定你以后能不能复现论文里的对抗样本、能不能 deterministic 跑鲁棒性评测——是 AI 安全实验的硬要求，所以单独讲透。

追问 1：np.random.seed(0) 到底是做什么的？

它给 NumPy 旧版”全局随机状态”（基于 Mersenne Twister 的伪随机数生成器）设了一个起点。设完之后，所有 np.random.rand / randn / randint / shuffle 产生的数列就被固定下来——同种子 + 同调用顺序 = 同结果，跨进程、跨机器（同 NumPy 版本）都一致。

要点：

  • 0 只是个整数；换成 42 会得到另一条同样可复现的数列，不是”0 更好”。
  • 它只重置一次全局状态。之后每次 rand() 都把内部状态往前推一格，所以连跑两次 rand() 结果不同是正常的（见追问 3）。
  • 为什么 AI 安全人要在意：复现别人论文的对抗样本、deterministic 跑评测，seed 就是”实验可复现”的开关。

追问 2：seed(0) 和新的 np.random.default_rng() 区别？

default_rng() 是 NumPy 1.17+ 的推荐新 API（Generator + BitGenerator，默认 PCG64 算法）。核心区别：


 np.random.seed + np.random.* np.random.default_rng(seed)
状态 改全局状态，所有代码共享 创建独立 Generator，互不污染
算法 MT19937（旧） PCG64（新，统计性质更好）
未来 旧接口已冻结，不再加新特性 官方主推，持续演进
复现粒度 全局 每个 generator 各自复现

⚠️ 关键坑：default_rng(0).random() 的数列 不等于 seed(0) 后 rand() 的数列——算法不同。论文/代码用哪种，你就得用哪种才能复现，别以为”同一种子哪边都一样”。

💡 常见误会：a = default_rng(1) 之后，每调一次 a.random(2) 就吐出下一段 2 个数、并把 a 的内部状态往前推——所以连调三次会得到三段不同的数（这正是你实测看到的现象）。seed 只固定起点，不是”每次调用都重置”。想拿回第一段，得重 a = default_rng(1) 才算”回到起点”。

而 a 和 b 互不干扰才是 Generator 的精髓：你调 b.random(2) 动的是 b 的状态，不会影响 a 的序列（旧全局 np.random 做不到这点）。实测印证：

追问 3：在 Jupyter/IPython 里为什么有时看起来”没生效”？

常见 4 个原因：

  1. 只 seed 了一次，后面又跑了随机调用 → state 已推进，再跑新 cell 不重 seed 就不同。
  2. 用了 default_rng() 没传种子 → 不带参数时每次从系统熵取新种子，不可复现。必须 default_rng(0)。
  3. 别的代码/库中途动了全局状态 → 比如 import 的某包在初始化时调用了 np.random.*，把你 seed 后的状态又推了一段。
  4. 只重跑了 cell 的”后半段” → 比如 cell 里先 seed 再 rand，你只重跑 rand 那行，state 已经不在 seed 起点了。

实操建议（写实验照做）：

  • 实验脚本开头统一 seed 一次，把值写死（如 SEED = 0），跑评测前 print 出来，论文里写”固定随机种子为 0”。
  • 新项目优先用 rng = np.random.default_rng(SEED)，后面所有随机都走 rng，别混用全局 np.random.*。
  • 注意：PyTorch / TensorFlow 有各自的随机种子（torch.manual_seed），NumPy 的 seed 管不了它们，学到时要分别设。

4 广播（Broadcasting）

先从末轴向前比较形状：每一对轴必须相等，或其中一个为 1；缺失的前置轴按 1 处理。广播后的数组未必真的复制了数据，关键是计算时如何对齐。

图中的 (2,3) - (2,1) 是每行减自己的均值；若得到 (2,)，末轴的 3 与 2 不兼容，会报错。更隐蔽的是方阵 (3,3) - (3,)：能够运行，但会按列对齐向量，未必是你想要的逐行操作。

追问：给 batch 的每个样本加一个阈值向量 thr=[0.1,0.1,0.1]，用广播写一行。

💡 广播让”小形状”自动对齐”大形状”，免去手写循环——向量化计算又快又简洁，PyTorch 里也天天用。

7 与范数（呼应数学篇 1.6）

学到这里立刻做｜LLM02 前置：令 M=np.array([[1.,2.,3.],[4.,5.,6.]])，比较 M.mean(axis=1) 与 M.mean(axis=1, keepdims=True) 的形状。用后一种写逐行中心化，断言结果每行均值为 0；随后运行 LLM02，找出 softmax 中两个 keepdims=True 分别保护了哪一步广播。

这就是对抗扰动预算 （扰动 δ 的 p-范数不超过 ε）里那个范数。试着把 x 改成 [1,1,1,1]，看 L2 与 L∞ 各是多少。

💡 L2 看”整体幅度”、L∞ 只看”最大那一维”。对抗攻击的扰动预算 ε 就是限制这个范数，决定攻击多”肉眼不可见”。

参考答案（§7 追问）：x 改成 [1,1,1,1] 时，L2 = √(1²+1²+1²+1²) = √4 = 2.0，L∞ = max(1,1,1,1) = 1.0。所以同一条向量，L2 看”整体幅度”、L∞ 只看”最大那一维”——这正是对抗预算 ε 限制的东西。

8 一个迷你演练：线性分类器打分

改一下 W 里某个数，看 pred 会不会变——这就是”权重微小改动 → 预测翻转”，对抗攻击的雏形。

💡 argmax 取”最大值的下标”= 预测类别编号。这一步正是分类模型最后一层做的事：打分给各类、选最高分。”权重微小改动 → 预测翻转”，对抗攻击的雏形。

参考答案（§8 追问）：把 W[1,1] 从 0.8 改成 0.59（只动 0.21）再跑，pred 就从 [1, 0, 0] 变成 [0, 0, 0]——样本 0 从类 1 翻到类 0。为什么这么小的改动就够？看原始 scores：样本 0 是 [0.24, 0.34]，两类只差 0.10（这个差距叫间隔 margin）；样本 0 的特征 1 是 0.5，所以 W[1,1] 每降 Δ，类 1 得分就降 0.5×Δ，只要 Δ > 0.10/0.5 = 0.2 就翻转。margin 越小，模型越”脆”。
