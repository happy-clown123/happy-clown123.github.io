中国 Agent 安全就业判断与能力路径

中国 Agent 安全就业判断（截至 2026-09-21）

使用动作：先完成本文阶段 A–D 和 Secure Agent 项目，再用 5–10 条仍有效的官方岗位重新做一次技能词统计。把每项 JD 要求映射到“课程知识、可运行代码、威胁模型、评测报告”四类证据；招聘信息变化快，投递前回官方页面核验。

定位：把“想做 Agent 安全”翻译成国内实际岗位名、能力证据与可执行学习路径。
数据边界：就业市场变化快；本文优先使用官方政策、研究机构和企业招聘页，聚合站职位只用于观察技能词，不用于推断全国岗位数或薪资。

1 结论

适合深入，但不建议把自己只定义成“Agent 安全专家”。

更稳妥的职业定位是：

AI/LLM 安全工程师（主线） + 应用安全/云安全工程底座 + Agent/MCP 安全专长

原因不是 Agent 安全不重要，而是它还是一个岗位少、要求宽、实战门槛高的新分支：

  • 确有专门岗位。中科院计算机网络信息中心在 2026-06-23 的官方招聘中直接使用“智能体安全研发工程师”，工作包含 memory 泄露/污染、目标劫持、工具滥用、运行时防护和端到端平台；但该次只招 2 人，要求硕士及以上。这同时证明“岗位存在”和“入口较窄”，不能据此推断全国岗位规模。中科院计算机网络信息中心
  • 大厂把它放在更宽的 AI 安全、云安全和前沿研究体系中。华为云安全隐私实验室的 2027 届 TopMinds 课题明确覆盖间接注入、工具劫持、越权、记忆投毒、MCP、沙箱和评测基准；同页博士岗位也把智能体安全攻防列入 AI 安全研究。该样本强调研究成果、系统功底和工程能力，不能当成普通本科初级岗位画像。华为云安全隐私实验室
  • 应用需求有政策推动。国务院“人工智能+”意见提出到 2027 年智能终端、智能体等应用普及率超过 70%，并强调安全可控与风险治理；这支持长期需求判断，却不能换算成招聘数量或保证出现大量同名岗位。中国政府网/中央网信办转载
  • AI 大盘在增长，但结构性门槛不低。中国劳动和社会保障科学研究院发布的人才报告称，三大核心区域汇聚超过 55% 的 AI 人才，并指出需求旺盛、高端短缺和区域/行业分布失衡；这是 AI 整体背景，不是 Agent 安全岗位统计。中国劳动和社会保障科学研究院

**因此：方向值得选，求职口径不能过窄。**你应该能投“AI 安全”、“大模型安全”、“AI Safety/评测对齐”、“云安全”、“应用安全”、“安全研究员”中涉及 Agent 的岗位，而不是只搜“Agent 安全”四个字。

2 岗位真正要什么

从官方岗位和当前招聘样本归纳，企业要的不是“会写 jailbreak prompt”，而是下表的复合能力。蚂蚁/字节的聚合站样本仅作技能词参考，投递前需回到企业官网确认岗位是否仍有效。

能力组 岗位里的表述 你需要的证据
传统安全底座 Web/主机/云/供应链/沙箱/权限控制中至少两项 PortSwigger 记录 + 一个可审计 policy gateway + Linux/网络实验
LLM/Agent 原理 Transformer、RAG、Function Calling、ReAct、MCP、Memory 自己搭的最小 Agent，能画清数据流而不是只调框架
威胁研究 间接注入、工具滥用、memory 投毒、供应链、运行时逃逸 threat model + 可复现攻击 case + 对应系统级防御
安全工程 schema、allowlist、per-tool authorization、token scope、沙箱、审计 可运行代码、单测、拒绝原因、脱敏日志
评测与运营 样本库、规则库、评测集、误报/漏报分析、回归测试 USR/ASR/UAR/FPR + 分场景失败分析，而非单一准确率
研究表达 跟踪论文、技术报告、专利/标准 一篇严谨复现报告；研究岗再加论文或高质量开源贡献

一个具体的职位样本显示，“智能体安全”已经包含 Agent Runtime、Skill/Plugin、MCP、Memory、供应链、沙箱、风险标签、评测集和告警运营，同时要求 Web/主机/供应链/权限控制等传统基础。字节跳动智能体安全能力专家（第三方招聘页）

3 适合你的路径

你目前学到 F（LLM 基础），下一步不应该立即深挖各种 Agent 框架。先建立可迁移的安全底座，再进 Agent 系统层。

阶段 A：把 F 真正验收

  • 跑通 llm01 BPE、llm02 attention、llm03 LoRA。
  • 能解释 role 只是模型输入结构，不是可强制执行的 access control。
  • 能分清预训练、SFT、偏好对齐和运行时 guardrail。
  • 验收物：三个实验输出 + 一张“模型不是权限边界”图。

阶段 B：补 G/H 的安全底座

  • G 重点：HTTP/TLS/DNS、身份与会话、OAuth 基本流程。
  • H 重点：输入校验、SQLi/XSS/SSRF、服务端授权。
  • Linux/Git 重点：进程权限、环境变量秘密、容器基础、依赖锁定。
  • 验收物：一份“传统 Web 漏洞如何在 Agent 工具链中放大”的对照表。

阶段 C：交叉学 J/K，不要只学 prompt 技巧

  • 用 J 建立 evasion/poisoning/extraction/inference 的攻击分类和评测意识。
  • 用 K01–K03 理解注入、越狱检测的局限、RAG 投毒。
  • 每个攻击都要写：资产、攻击者能力、信任边界、成功条件、真实后果、回归测试。
  • 验收物：一份不依赖危险 payload 清单的 LLM 安全评测报告。

阶段 D：做 Agent 安全专项

  • 学 03-core/llm-security/agent-security.md，跑 K04–K08，并扩展 projects/secure-agent/。
  • 深入四条线：agent hijacking、tool authorization、memory provenance、MCP identity/supply chain。
  • 在 AgentDojo 或自建纯本地环境中增加攻击-良性配对 case。
  • 验收物：Secure Tool-Using Agent 作品集项目。

阶段 E：选择工程或研究分支

工程分支：加强 Go/Java/Python 服务端、OAuth/OIDC、容器沙箱、云 IAM、日志与告警、Semgrep/CodeQL。目标是能做运行时网关、检测规则和事件处置。

研究分支：加强 PyTorch、后训练（SFT/DPO/RLHF 的目标与评测）、自适应攻击、benchmark 设计、统计显著性与论文写作。目标是能复现 AgentDojo 类工作并提出可验证改进。

4 作品集的最小证据链

作品 证明的能力 不合格的做法
Agent threat model 系统分解、资产、信任边界、滥用场景 只抄 OWASP Top 10 标题
Policy gateway 确定性强制、参数级授权、fail closed 只在 system prompt 里写“不要作恶”
Memory security provenance、tenant、TTL、读时授权 用关键词删除“ignore”
Evaluation harness 良性-对抗配对、USR/ASR/UAR/FPR、失败复盘 只报一个 ASR 或准确率
Reproduction report 论文阅读、实验控制、边界诚实 只转述摘要，没有代码和原始结果

5 投递时的岗位搜索词

不要只用一个关键词。用下面的组合，然后按 JD 的实际攻击面筛选：

  • AI 安全 / AI Safety / 大模型安全 / 模型安全评测
  • 智能体安全 / Agent 安全 / MCP 安全 / AI 红队
  • 云安全 + Agent / 应用安全 + LLM / 供应链安全 + AI
  • 安全研究员 + 大模型 / 安全开发 + 智能体
  • 模型对齐 / 安全评测 / 可信 AI / 内容安全（需辨别是否只做审核）

地域上，优先关注北京、上海、深圳/广州、杭州、成都、西安、南京等 AI/网安研发集中地；这是根据人才集聚与官方岗位地点做的方向性判断，不是城市排名。

6 什么情况下应该调整方向

如果经过 G/H/K 与 K04–K08 后，你发现自己：

  • 喜欢流程、规范、审计，不喜欢写系统代码：转向 AI 治理/数据合规/模型风险管理，学 N 模块。
  • 喜欢漏洞、沙箱、权限和云系统，对训练算法一般：走 应用安全/云安全 + Agent 安全专长，这是就业面更宽的方案。
  • 喜欢模型行为、实验和论文，能接受更高学历门槛：走 LLM 安全研究/对齐评测/Agent 安全研究。
  • 喜欢拿 LLM 做检测、SOC 和漏洞挖掘：走 AI for Security，但要清楚这是 L 副线，不是“保护 AI 系统”的同一问题。

对你当前的定位，最推荐第二条打底、第三条拉高上限：先成为会做安全工程的 AI 安全人，再成为 Agent 安全专家。
